## 2. Semantics, identity, and execution observations

### 2.1 Two compiler contracts and one runtime contract

A structural quotient and a rewrite that removes computation do not have the same observational contract. Expose that distinction explicitly rather than pretending that every optimization preserves identical microsteps.

| Contract | Permitted changes | Required preservation |
|---|---|---|
| **Structural compilation** | Static code/descriptor sharing and typed relocation under P01. | Annex A's step-for-step relation, including logical work boundaries, effect/failure/cleanup order, and dynamic identity. |
| **Semantic compilation, explicit semantic contract** | Checked changes to private implementation structure, including fewer instructions, different internal calls/captures, and fused private computation. | The external semantic contract below; all original validation obligations; runtime safety and authority. Internal state shape and the number of internal steps can differ between newly compiled images. |
| **World execution acceleration of one image** | Physical layout, allocation reuse, cached derived metadata, or fewer native dispatches. | Exactly the behavior of the same admitted image under its runtime API, including its quantum/step accounting and observable interruption boundaries. |

**Semantic compilation is not a silent compatibility change.** This assignment authorizes the audit and deliberate migration of owned applications to the qualified semantic contract where their existing guarantees permit it; no new optimizer opt-in is needed after that migration. A change of image hash alone does not authorize changing a client’s source-level quota, instruction-sensitive policy, cancellation protocol, or step-based security control. An application that genuinely depends on identical cross-build work boundaries retains the structural contract unless an independently validated realization preserves them. Both contracts run P01 and all other qualified transformations applicable to their promises through one canonical implementation.

Semantic compilation may return a different intermediate state or reach a different internal point after the same finite quantum. Consequently, cancellation injected after an arbitrary number of internal steps can act at a different semantic point. This is an explicit limitation of the semantic contract, not a hidden equivalence claim. Cancellation supplied at corresponding external semantic boundaries must preserve its behavior. Before migrating an Agent application to semantic compilation, audit quantum, cancellation, approval, speculative execution, and quota policies and bind the application to the resulting documented contract. This audit is required implementation work, not permission for indefinite predecessor coexistence or weakened protections.

No “unsafe optimization” mode is specified. Neither mode permits dropping failures, changing demand, erasing effects, merging authorities, or using unsound analyses. The difference is the set of internal operational observations promised across **different compiled images**.

### 2.2 External semantic contract

For the same admitted source/object inputs and corresponding valid environmental replies, the transformed program must preserve:

- Typed external input/output contracts, result values, authored failure payloads, and observable effect identity/payload/order.
- Lazy demand, termination/divergence, operation-body order, handler selection and reentry, deep/shallow distinctions, answer transformation, and user-authored yields.
- Ownership/borrowing obligations, resource authority, region lifetimes, cleanup establishment and unwind order, and cancellation behavior at corresponding external boundaries.
- Multi-shot branch behavior and all observable aliasing/separation relationships. An object that has no observer may be eliminated only under a package-specific escape/demand/lifetime argument; observable objects cannot simply be merged.
- Agent classification, exact-proposal binding, approval, speculative restrictions, and execution/commit protections.

“Pure” is not “total.” “Linear” is not “nonescaping.” “Same schema” is not “same value.” “Same code” is not “same dynamic object.” A declared empty residual effect row is not proof that the body cannot fail, diverge, allocate identity, observe state, or manipulate control.

For deterministic fragments, establish matching semantic outcomes/traces. For nondeterministic or environment-driven fragments, use corresponding choices and a relation covering all supported choices, not only the benchmark responder. For divergence, finite prefix tests are evidence about those prefixes; a divergence-sensitive simulation argument must prevent an infinite internal loop from being transformed into termination or vice versa.

### 2.3 Failures, arithmetic, and evaluation order

Boundary's own primitive semantics govern every rewrite. Do not import LLVM poison/undefined-behavior reasoning, unrestricted ring laws, host-language overflow, or mathematical integer identities into checked fixed-width operations.

A potentially failing computation cannot be deleted solely because its result is unused. Moving a computation earlier requires proving both that it is allowed to execute on that path and that moving its failure cannot alter the first observable failure. Speculative execution requires stronger permission than common-subexpression reuse of a value already computed successfully.

For a primitive over checked values, define a semantic result of the form:

```text
Result = Value(canonical_value) | Failure(authored_failure_identity, payload)
```

Proofs must compare that result and any preceding observations. A correct algebraic result after an intermediate overflow does not rescue a rewrite. Tests must include signed extrema, zero divisors, invalid indices/variants, bounds, capacity failures where contractual, and primitive-specific evaluation order.

## 3. Mathematical design rules

The Freyd connection is a guide to **program-relative representation and factorization**, not an unconditional identification of a finite compiler transformation with the full adjoint functor theorem. Its categorical hypotheses and the completeness of an exponential object do not hold merely because a program has a finite set of constructors. [R1]

Use the following equations as design obligations, with the appropriate effectful/operational refinement of equality where required.

### 3.1 Quotient implementation distinctions

```text
Closure[S] = coproduct over constructor c of Environment[c]
apply : Closure[S] × Argument -> Result
```

P01 removes redundant code/description distinctions within compatible contracts. It does not identify `A + A` with `A`, merge environments, or decide all behaviorally equivalent functions. Its reference-graph relation is finite and explicit.

### 3.2 Factor an environment through sufficient information

```text
original(environment, argument)
    = reduced(summarize(environment), argument)
```

P07 implements this law for selected structurally recognized families and the synthesized affine state spaces in Section 13. Repeated/stateful use additionally requires update closure, not only next-call output factorization. The summary must be sufficient for **all permitted uses**, not just sampled calls. It must not move demand, failure, allocation identity, or resource disposal to a different observable point. A less informative mathematical value is not automatically a cheaper physical representation; measure construction and retention costs.

### 3.3 Replace syntax of a continuation by its action

```text
act(identity, x) = x
act(compose(r1, r2), x) = act(r1, act(r2, x))
```

P15 exploits representations of compositional actions. Associativity can make accumulated actions cheaper than chains of explicit contexts; noncommutative actions retain orientation. P16 handles constructor contexts where the result must still be built. These are distinct from merely folding identical function bodies. [R2] [R3]

For a four-bit XOR example, a pending chain of masks can be summarized by their XOR. That illustrates a law, not permission to change Boundary's public integer widths or to replace checked addition with modular addition. A runtime-length chain still requires linear processing of its masks; a constant-size retained summary does not imply constant-time execution.

### 3.4 Fuse producers and consumers

```text
h ∘ alpha = beta ∘ F(h)
    implies, under the required initial-algebra assumptions:
h ∘ cata(alpha) = cata(beta)
```

P13 and P14 use recognized eliminator/producer structure to avoid intermediate values. The familiar total-pure equation must be strengthened for partiality, demand, effects, and resource semantics. P12 handles interaction between handlers separately: effects do not commute merely because both are internal. [R10]

### 3.5 Abstract rather than equate

```text
alpha(X) <= a  iff  X is contained in gamma(a)
```

Use sound abstraction for constructor, constant, range, demand, and escape analysis. An abstraction may lose information; a transformation is authorized only by conclusions that remain sound. A coarse abstract equality is not proof that concrete values or programs are equivalent. Finite-height domains or explicit widening plus post-fixed-point checking establish termination. [R4] [R5]

### 3.6 Search is not proof, and cost is not semantics

Equality saturation, SMT search, profiling, and partial evaluation may find candidates. Only checked laws and sound preconditions authorize them. Optimize over valid representations using a cost model; never use measured speed, a low hash distance, or a passing sample as an equivalence certificate.

No blanket “free theorem” may be inferred from a Zig generic parameter when the implementation can inspect types, invoke arbitrary host code, or observe representation. Law-based rewrites must match trusted, checked library implementations or validate explicit facts from executable records. Do not add an author-supplied `assume_law = true` escape hatch.

### 4.1 Reuse the existing executable representation

Operate on the current stable-activation records and reuse typed relocation, schema equivalence, primitive semantics, ownership traits, reachability, and admission. A temporary analysis view is allowed. Do not create a second persistent IR simply to imitate another compiler.

Implement only shared infrastructure that at least one delivered transformation uses. A small internal pass table, facts owner, and change summary are sufficient; no plugin architecture or serialized optimization language is required.

A minimal pass boundary has these conceptual values:

```text
Input:  admitted immutable records, contract, objective, optional profile,
        deterministic work budget, optional caller-owned observations
Output: unchanged or changed owned records, exact applicable admission facts,
        outcome, attributable statistics, optional temporary origin map
```

The library must not write files or logs unconditionally. Scratch and proof witnesses must not become part of BPI3, BMO1, PST3, or runtime identity. Independent compilations must not share mutable optimizer state.

### 4.2 Fact identity and invalidation

Every derived fact is tied to an immutable program epoch and, where necessary, a function/call-context identity. Cloning code, changing captures, editing a CFG, relocating IDs, or changing an effect/borrow contract invalidates the corresponding facts. Either recompute or establish an explicit transport theorem for an exact bijective relocation. Do not retain a useful-looking old singleton constructor fact after introducing a new constructor.

Static code-equivalence classes and abstract call contexts are different identities. Sharing code need not force all callers into a single imprecise analysis context. Conversely, retaining provenance does not automatically justify a context-sensitive conclusion: the analysis must actually distinguish those contexts.

### 4.3 Stable-slot value and control facts

Build a temporary definition/version graph over stable slots, not an assumption that a slot is already SSA. Each edge assignment reads the predecessor environment; assign all destinations simultaneously. Model joins and back edges explicitly. A phi-like analysis node is not a new wire record.

Track roots, feasible edges, reaching definitions, dominance/postdominance where used, loop/SCC membership, and custody transitions. Control effects, suspension, resumption, handler reentry, exceptional cleanup, and regions are part of the graph semantics. A simple normal-return CFG is insufficient for moving owners or mutable reads.

Required value domains include constants, finite constructor possibilities, variant possibilities, selected product-field facts, integer intervals/known bits, and bounded sequence-length relationships. Distinguish:

```text
unreachable path
reachable but unknown value
known ordinary value
possible authored failure
```

Do not interpret “unknown” as zero, “uninitialized” as unreachable, an empty observed set as impossible, or a finite upper bound as an exact length. External inputs and unresolved imported behavior start conservatively. A finite-set precision cap must widen to an explicit unknown/top element, never discard possibilities.

### 4.4 Demand, escape, and environment facts

Demand facts distinguish: not needed at all; needed only for ownership/disposal; needed as a value; needed only through particular fields; potentially forced; necessarily forced; and retained beyond the current region/activation. “Unused ordinary result” does not imply “no cleanup obligation.” Demand must be computed after relevant branch and call specialization.

Escape facts identify return/export, storage in another escaping value, installation in a handler, suspension/checkpoint retention, capture by a resumption, multi-shot retention, and unknown use. A closed lambda can still escape; a one-shot value can still cross a suspension. Model call summaries conservatively and validate them at their use sites.

An environment summary or scalar replacement must account for the transitive retained object graph, not just the number of descriptor fields. Performance instrumentation must distinguish retained bytes, peak bytes, and total allocated bytes.

### 4.5 Effects, mutation, speculation, and control

Derive a conservative operation/function summary with independent dimensions:

| Dimension | Examples of facts required by consumers |
|---|---|
| External effects | Nominal operation identities and handler/evidence dependencies. |
| Failure | Possible authored faults and their ordered evaluation dependencies. |
| Termination | Known finite/total fragment versus may diverge. |
| State | Read/write/allocation sets, alias classes, and unknown memory effects. |
| Identity | Creates, consumes, exposes, or compares identity-bearing objects. |
| Ownership | Copy/drop/borrow/move permissions at this occurrence. |
| Control | May suspend, resume, clone, yield, install handlers, or change custody. |
| Retention | Values/owners that can survive exit, cancellation, or checkpointing. |

Reuse existing traits and checker results; do not substitute a second ownership checker. MLIR's separation of effects and speculation safety is precedent for distinguishing these permissions. [R7]

In the first GVN/PRE/LICM implementations, restrict to immutable copyable data and proved-total operations. Extend mutable-read reuse only with a separately tested alias/version analysis. Unknown calls, effects, resumption, and potentially aliasing mutation invalidate dependent memory facts. No blanket “all reads are pure” rule is allowed.

### 4.6 Fixed points and checked summaries

Use sparse worklists, SCCs, and dependency edges. Reach the actual fixed point of the chosen finite domain. Infinite-height analyses require a documented widening strategy and an independently checked sound post-fixed point; stopping after an arbitrary round is not proof.

For summaries used to authorize a transformation, a checker must verify root coverage and conservative transfer across every relevant edge/call against the actual records. A profile is never a transfer proof. A finite domain can be deliberately coarse; missed precision is reported as a missed optimization, not silently converted into certainty.

Do not prebuild a universal abstract interpreter for every possible future property. Implement the product of domains incrementally around P02, P03, P07, P08, and P11, while preserving sound information exchange between them. [R4] [R5]

|---|---|---|
| Raw structural correspondence | P01 and pure renamings. | Actual input/output comparison under complete typed maps and local bijections. |
| Checked local rewrite with fact certificate | Constant folding, direct calls, DCE, GVN, capture trimming, loop transformations. | Rule identity, exact matched records, locally checked preconditions/summaries, replacement construction, and actual-output comparison. |
| Law/schema-specific simulation | Fusion, contification, context compression, reuse, supercompilation. | Explicit relation and invariants for the supported family; checked structural instantiation; evidence for demand, control, and resource behavior. |

Maintain a small code-adjacent registry of proved rewrite families. It is not a user-extensible law language. A new primitive/record field must force an explicit semantic classification through exhaustive handling or failing tests. Unknown opcodes are not silently treated as harmless.

Distinguish `no_proof` during candidate discovery from a false purported proof. A matcher may conservatively decline before building a certified candidate. Once a candidate claims the rule's obligations and the independent checker rejects the witness or emitted records, that is an optimizer error, not a normal profitability rejection. P01 retains Annex A's stronger explicit failure rules.

Do not require an SMT solver for production acceptance. Offline synthesis may propose finite rules, but their implemented schemas and side conditions must enter the checked rule registry. Bounded SMT validation is not an unrestricted proof over recursive Boundary programs. [R24]

### 4.8 Small trusted core, nontrivial validation

The validator must not simply rerun the finder, trust its fingerprints, or check only that both programs admit. A correctly typed replacement of `41` by `42` is the mandatory counterexample to such a design.

The correctness argument must cover initial-state correspondence, each relevant operation, observations, dynamic identity/ownership, and divergence-sensitive progress. For transformations allowing several internal steps to correspond to one, provide a well-founded rank or another justified condition excluding infinite unmatched internal stuttering. Do not assert that equal final results on terminating examples establish equivalence.

### P02 — Reduced-product value analysis and sparse conditional propagation

### P03 — Constructor-flow-directed application specialization

### P04 — Global value numbering and common-subexpression reuse

### P05 — Dead computation, dead argument, and dead store elimination

**Layer/contract:** Boundary data-only; semantic.

**Negative witnesses:** unused division-by-zero computation; mandatory resource cleanup; discarded but effectful argument; an intermediate checkpoint observing a store; closure retained only by a resumption.

### P06 — Partial redundancy elimination

**Layer/contract:** Boundary data-only; semantic.

Implement availability/anticipatability analysis for a restricted set of total, copyable, immutable expressions. Respect parallel edge assignments and critical-edge structure; do not put path-specific computation unconditionally into a predecessor with other successors.

The minimum implementation may avoid speculative placement entirely by choosing latest placements that execute only on paths where the original later evaluation must occur. An insertion that can execute on a formerly unevaluated path requires a separate speculation proof and retention-cost check.

**Minimum witness:** a diamond where one arm already computes an expression and the post-join block repeats it. The transformed execution computes it once on each path, with no extra computation on an early-return arm.

**Negative witnesses:** potentially failing expression; early exit; borrowed owner unavailable on one predecessor; differing custody; mutable operand version change.

**Acceptance/metric:** path-placement, dominance, demand, and expression-equivalence certificates. Report removed dynamic evaluations on each path, not just static instruction count, since PRE can grow static code. [R8]

### P07 — Demand-driven environment reduction and sufficient summaries

**Negative witnesses:** unused-looking cleanup owner; mutable read in summary; delayed failing projection; original capture shared elsewhere; externally inspectable/identity-sensitive payload.

### P09 — Call-pattern specialization, worker/wrapper, and selective inlining

### P10 — Contification and join-point conversion

### P12 — Handler elimination and law-directed handler fusion

### P14 — Demand-preserving hyperfunction and thunk fusion

### P15 — Algebraic continuation/context compression

**Layer/contract:** Boundary data-only; semantic.

**Minimum witnesses:** runtime-length XOR context chain at lengths 1, 16, 256, 4096; noncommutative finite action chain; an existing generated code pattern recognized without author centralization. Do not replace the real application with the synthetic chain in consumer measurements.

**Negative witnesses:** checked arithmetic overflow; mask expression with effects/failure; individually resumed context frame; escaped context; incorrect composition orientation; intermediate user yield; resource-bearing context.

**Layer/contract:** Boundary for explicit slot transformations; World for physical backing storage. Preserve the existing qualified slot-order pass.

Separate bijective logical renaming from many-to-one physical allocation. Logical slots and dynamic activation versions are not interchangeable. Two slots may share backing storage only when their live ranges, ownership obligations, alias exposure, schema/layout requirements, and all retained activation versions make them noninterfering.

Implement an interference/liveness-based packing experiment for eligible instruction temporaries. For a logical slot-coalescing rewrite, use exact compatible schemas and preserve repeated definitions/parallel edge semantics. For World packing, keep logical IDs intact and materialize the correct values at checkpoint/inspection; a frame retained by a resumption must not read a subsequently reused cell.

Do not replace the current selective bitset-fragmentation optimization with an unconditional global reorder. The existing performance history documents that representation choices can cross allocation thresholds; measure those effects rather than treating fewer slots/words as automatic wins. [B6] [B9]

**Minimum witnesses:** disjoint temporary lifetimes share physical storage; simultaneous swaps remain correct; a retained prior activation prevents unsafe reuse; threshold cases around a storage/bitset boundary.

**Negative witnesses:** same slot ID in different activation versions; multi-shot snapshot; borrowed live value; incompatible physical layout; cleanup referring to a reused value; state save midway through a loop.

**Acceptance/metric:** independently checked interference/availability/retention map, ordinary admission, and same-image snapshot comparison for physical packing. Measure logical slot counts, physical bytes, analysis-set storage, and peaks separately.

### P23 — Profile-guided specialization and layout

**Layer/contract:** compiler search policy and optional World layout; never a source of semantic truth.

Accept an explicitly supplied immutable profile bound to the relevant input image/source tuple, toolchain/profile schema, and logical locations. Reject or explicitly ignore stale/incompatible profiles; do not guess correspondence by function name. Collection must be opt-in and local; no telemetry service is required.

Use profiles to allocate P09/P19/P21 specialization budgets, prioritize candidate evaluation, and choose among already valid layout/dispatch alternatives. Rare paths remain present unless statically unreachable. A frequently monomorphic call does not become a proved singleton constructor. Speculative guarded specialization is outside the minimum deliverable unless an existing exact guard can preserve the generic fallback without a new opcode.

**Minimum witnesses:** a hot known constructor path is specialized preferentially within a fixed budget; an unobserved but reachable alternative still behaves correctly; stale profile handling; identical input/profile/options produce identical output.

**Negative witnesses:** zero samples treated as impossible; profiles from another image; malformed counter arithmetic; source IDs confused with relocated IDs; compile output dependent on live wall-clock timings.

**Acceptance/metric:** profile parsing/identity checks plus the same proof for every chosen transformation as in profile-free compilation. Report held-out workloads and profile collection overhead; no training-only speedup claim.

### P24 — Restricted affine/polyhedral loop optimization

**Layer/contract:** Boundary data-only; semantic. This is a restricted schedule transformer, not an LLVM/Polly frontend.

Recognize a static-control region with bounded integer iteration domains, affine guards/index relationships, and supported dependence behavior. Begin with rectangular two-dimensional counted loops. Implement interchange and fixed-size tiling only after proving a bijection of iteration points and preserving every dependence/order-sensitive observation.

For the minimum executable witness, use checked in-range immutable buffer reads or total index computations and a proved associative/commutative total reduction such as fixed-width XOR. Preserve all prerequisite shape/bounds validation. An output-building loop with order-sensitive appends is not interchangeable merely because its indices are affine.

Generate ordinary current loop/primitive records. Tiling must prove coverage of partial final tiles without overflow; interchange must prove that no mutable alias, failure, resource, yield, or handler interaction requires the old order. Do not add SIMD opcodes or an application-specific kernel. Lack of benefit rejects an uneconomical candidate or leaves its economic qualification explicitly unresolved; it is not a reason to ship a second optimizer behind a disabled-by-default product switch or falsely report a benefit.

**Minimum witnesses:** 2D interchange; tiled loop with nonmultiple dimensions; zero/one-sized domains; a dependence-carrying near-example that is rejected. Exhaustively compare small domains and provide the general index-domain proof.

**Negative witnesses:** triangular domain outside the implemented recognizer; aliasing writes; checked-overflow reassociation; first-failure order; effectful iteration; incorrect final tile; source-level per-iteration quota.

**Acceptance/metric:** affine domain, schedule-bijection, dependence and primitive-totality certificates. Report compile cost, image growth, locality/runtime effect, and cases not recognized. Polly is precedent, not a required dependency or a proof of this implementation. [R20]

### P25 — World superinstructions and dispatch acceleration

**Layer/contract:** World; **same-image exact execution contract**.

Recognize repeated short sequences in already admitted records and execute them with fewer native interpreter dispatches. Keep BPI3 and logical instructions unchanged. Use a small derived execution plan or specialized dispatch path inside the existing interpreter; no new VM, JIT, serialized microcode, or persistent service.

Begin with short pure total scalar sequences with no allocation, suspension, custody transition, or observable side effect. For each pattern, preserve original logical instruction accounting. If the remaining quantum ends inside the sequence, execute only the permitted prefix or use the baseline path. Do not execute the whole batch and charge the quantum afterward.

Any later pattern containing failure or allocation must identify the exact original logical point and materialize the correct state there. Inspection/checkpoint/cancellation interfaces must not see an invented fused opcode or an unrepresentable partial state. Derived plans are invalidated with their admitted image/Prepared owner and never accept naked unadmitted records.

**Minimum witnesses:** one two-operation and one longer frequently occurring supported sequence; every quantum cut from zero through sequence length plus a suffix; prepared and fresh execution; checkpoint/restore at every permitted cut.

**Negative witnesses:** failed middle operation; unknown effect; plan reused for another image; allocation exhaustion; cancellation during a pending cleanup; inconsistent logical work charge.

**Acceptance/metric:** per-pattern same-image simulation and per-prefix state checks. Report native dispatches versus logical operations, preparation cost/memory, and native/WASM timings. A lower dispatch count is not a lower logical work count.

### P26 — Uniqueness-based reuse, precise retention, and regional allocation

**Layer/contract:** World physical storage, optionally informed by independently derived Boundary facts; same-image exact logical behavior.

Inspect the current storage/collection implementation before changing it. Reuse an existing object's storage for its successor only when no live alias, checkpoint, resumption branch, or cleanup action can observe the previous representation. Copyable type traits do not prove dynamic uniqueness; linear use does not prove nonescape.

Start with one concrete consumed private node/frame class whose layout and initialization rules admit safe reuse. Maintain logical identity/versioning, invalidate stale physical references, and preserve transactional failure/retry behavior. For multi-shot sharing, use the existing persistent/copy-on-write discipline or a proved equivalent fallback; do not destructively update shared history.

Also remove unnecessary retention in a selected frame/owner path, and evaluate stack/region/arena allocation for a proved nonescaping class. Reuse precise existing reference/ownership information; a wholesale replacement collector or a claim that Perceus's theorem now proves World is not required or permitted without separate justification.

**Minimum witnesses:** a consumed node's storage reused; the same shape with an alias takes the non-destructive fallback; a retained continuation version survives; an eligible short-lived allocation avoids long-lived storage; physical failure leaves authoritative input reusable.

**Negative witnesses:** weak/indirect alias; saved state; cleanup reference; incompatible size/alignment; partially initialized replacement; generation reuse/ABA confusion; branch-local mutation.

**Acceptance/metric:** uniqueness/lifetime/layout checks and state relation over the actual storage implementation. Count allocation traffic, peak live bytes, retained bytes, reuse hit/fallback counts, collection work, and checkpoint costs independently. [R15] [R21]

### P27 — Typed equality saturation for pure regions

**Layer/contract:** Boundary optimization search; semantic, with finite deterministic budgets.

Implement a small internal e-graph or equivalent equality-saturation experiment over eligible acyclic pure total value regions. Nodes carry exact schemas, operand identities, primitive semantics, and proof-relevant preconditions. Do not place mutable reads, ownership transfers, effects, thunks, or control operations into an untyped congruence class.

Every union is justified by a registered law instance. Keep a reconstructible proof explanation; extraction must yield a finite actual expression/record graph and a checked proof. E-graph cycles are not recursive execution and must not result in infinite extraction. Resource exhaustion retains a fully checked incumbent, never an unfinished equality guess; document saturation versus budget exhaustion.

Start with bitwise identities, associativity/commutativity for exact total primitives, cancellation, and construction/projection identities already proved safe. The minimum interaction witness must require more than one rule, such as cancellation exposed only after reassociation. Check graph-sharing cost after actual materialization; additive tree cost is only a search heuristic.

**Minimum witnesses:** interacting rewrites; typed nonmerge; finite extraction from cyclic equivalence classes; budget exhaustion; actual emitted output mutation rejected by the proof checker.

**Negative witnesses:** checked arithmetic falsely treated as a ring; `0 * failing_expression`; differing schema widths; borrowed data; reuse of a stale analysis fact; cheapest tree duplicating expensive shared computation.

**Acceptance/metric:** independently replayed rule proof plus actual-output validation. Report search nodes/classes/unions, proof cost, candidate count, exact final size, and execution outcome. Ordinary compilation must not require an external e-graph service. [R17]

**Version-2 extension:** Section 13's matrix synthesis establishes state-representation validity independently of this expression search. P27 may optimize the resulting pure entry/update/output expressions and compare coordinate bases, but it must not infer dynamic-state equivalence from an e-graph of one output expression. Materialize and recheck the complete state update and all observers after extraction.

### P28 — Offline SMT-backed superoptimization and rule discovery

**Layer/contract:** optional development/test tool; not a production compiler/runtime dependency.

Provide a reproducible offline extraction/search/check loop for a restricted finite bitvector fragment of actual Boundary primitives. Encode exact width, input constraints, authored failure result where supported, and evaluation requirements. Search bounded candidate DAGs and ask whether a counterexample to the proposed equivalence exists.

Treat `unknown`, timeout, unsupported opcode, and incomplete encoding as no proof. Separate source and target encoders or include independent finite exhaustive checks at reduced widths to detect correlated modeling mistakes. Preserve the actual counterexample input and minimize it into a regression fixture.

A solver's answer does not directly authorize an arbitrary production rewrite. Promote a discovered **rule schema** only after adding its explicit side conditions, checked instantiation, semantic argument, and negative tests to the internal rule registry. Do not import LLVM refinement rules involving poison/undefined behavior. Souper is conceptual precedent; its retrieved repository is archived, so do not assume it is a maintained turnkey dependency. [R18]

**Minimum witnesses:** one automatically rediscovered valid bitvector optimization; one plausible false rewrite disproved with a concrete input; exact handling of `unknown`/timeout; a discovered rule instantiated through the production checker; a failure-order counterexample rejected by the fragment boundary or full encoding.

**Acceptance/metric:** pinned tool/solver inputs, replayable queries and outcomes, checked rule integration, compile-time and search cost. An exhaustive proof at width four is not a proof for width 64 unless a width-parametric argument is also supplied.

### P29 — Controlled partial evaluation and supercompilation

**Layer/contract:** Boundary data-only semantic search; shares P09's specialization machinery.

Drive a known first-order fragment under a static abstract environment, simplify known control/value structure, memoize encountered specialization configurations, and fold recurring configurations into residual functions. Stop at unknown effect/control boundaries and residualize them; never run arbitrary host emitters or invoke environmental tools.

Implement a termination control based on a finite abstract configuration space or homeomorphic embedding plus generalization over a documented well-quasi-ordered representation. Raw ever-growing constants, unrestricted stacks, or nominal labels cannot be casually assumed to satisfy the termination argument. Generalize growing static values to dynamic parameters when appropriate. Also enforce deterministic resource budgets as a defense, not as a substitute for soundness.

The minimum recursive rule targets a pure known helper/consumer with a static constructor/configuration parameter and a dynamic decreasing data argument. Demonstrate driving across a recursive boundary, folding into a finite worker, and preserving demand. Residual recursive workers require an induction/simulation argument; bounded testing alone is not enough.

**Minimum witnesses:** recursive specialization producing a finite worker; growing-static-parameter example triggers generalization rather than endless expansion; unknown effect is residualized in place; memoized equivalent specialization reused.

**Negative witnesses:** evaluation of a delayed divergent branch; configuration-sensitive emitter; incorrect fold of merely similar states; changed failure order; infinite specialization hidden as a clean budget exit.

**Acceptance/metric:** driving/folding derivation, termination/generalization rule, final worker certificate, and ordinary admission. Report driven states, folded states, generalized parameters, residual size, budget outcomes, and dynamic work. [R11] [R22]

### P30 — Optimize analysis and construction infrastructure itself

**Layer/contract:** compiler/linker implementation; output- and diagnostic-neutral except where a separately enabled transformation changes them.

Use indexed lookups, sparse deltas, SCC worklists, and partition representations to avoid repeated whole-program scans and quadratic materialization of equivalence pairs. Reuse existing worklist infrastructure rather than adding another generic solver. Prefer exact hash-indexed schema/literal interning when measurement demonstrates a scaling problem; exact comparison must resolve collisions.

Reserved/recursive schemas require special handling: do not leave stale interning keys after a schema definition changes. Cache only immutable facts or maintain correct invalidation. Do not identify nominal entities by structural fingerprints. Optimize temporary storage lifetimes and candidate release; do not retain entire compiler arenas or multiple complete candidate graphs merely to save one copy.

No persistent/global cache is required. Any local memoization key includes every relevant semantic input and belongs to the current compilation owner. Repeated compiles, allocator address reuse, different source configurations, and concurrent worktrees must not cross-contaminate results.

**Minimum witnesses:** growing mostly-unique and duplicate-heavy graphs; forced hash collisions; recursive schema reservation/definition; output/diagnostic equality with the implementation improvement disabled; allocation-failure cleanup.

**Acceptance/metric:** exact before/after semantic and byte comparisons; counts of lookups, comparisons, propagation visits, copied elements, and retained scratch. Maintain measured source construction, optimizer, linker, admission, and runtime costs as separate categories. [R4] [R6] [R23]

### P31 — Source-free link-time optimization and checked modular summaries

**Layer/contract:** Boundary data-only linker, with Agent propagation; structural or explicit semantic as selected.

Expose the same shared analyses and transformations at the closed-link boundary. Decode/admit all original components, resolve nominal bindings and instances, discharge original interfaces/borrow guarantees, construct the closed admitted baseline, then optimize. Original unreachable false contracts must not disappear before checking.

Derive summaries from checked object bodies/contracts already present in the selected BMO1 representation. Do not invent trusted sidecar assertions or change BMO1 to fit the optimizer. Open-component analyses must remain conservative about imports. New global coalescing is deferred to closed linking as required by Annex A; local source-component transformations may run only under their explicit semantic contract while preserving exports/import guarantees.

Record-only optimizations must not depend on source names, native emitter callbacks, source ASTs, Agent modules, or World during linking. Law-based recognition from components must inspect actual emitted bodies. Keep independently compiled nominal identities distinct unless explicit bindings unite them.

**Minimum witnesses:** independent-process objects expose a cross-component singleton call, capture reduction, and private code sharing after link; a linked law-recognizable producer/consumer pair; the same closed program through direct and linked routes has corresponding behavior; false summaries reject.

**Negative witnesses:** unknown import treated as pure/total; equal-named private effects merged; export signature changed; borrow-selector relocation wrong; optimization bypasses original contract validation; semantic option stops at an Agent wrapper component instead of reaching final link.

**Acceptance/metric:** original and final admissions, transient summary validity, complete typed relocation, and source-free runtime-independent build/run of the linker. Report per-path opportunities and output differences; direct and linked images need not have identical catalogue ordering.

**Version-2 extension:** P31's final-link coverage includes Section 13's private affine capture/worker cycle, checked observation census, and local representation conversions. No source-emitter tags or caller-supplied unchecked state summary may replace record-level evidence.

## 6. Pipeline, interfaces, and component integration

### 6.1 One canonical pipeline, explicit semantic contracts, no P01 switch

Use one authoritative implementation, shared by typed authoring, direct lowering, the standalone data-only linker, and Agent’s final compiled-tool link. Retain source-API conveniences only for concrete current responsibilities, not compatibility with a retired compiler route.

```text
CompilationPolicy:
    contract = structural | semantic
    objective = size | balanced | speed
    work_budget = optional deterministic resource budget
    image_growth_limit = optional explicit byte limit
    profile = optional validated profile input

Invariant:
    every production closed compilation and final link invokes P01
    no policy value selects an old compiler or bypasses coalescing
```

The contracts describe different observable guarantees, not alternative implementations. Structural compilation includes mandatory P01 and all qualified step-preserving transformations. Semantic compilation includes mandatory P01 and qualified applicable semantic transformations after the owned-consumer audit. Preserve genuine step-sensitive applications and same-image World behavior. Do not globally flip a semantic default before performing the audit; completing that audit and migrating eligible ordinary owned consumers is part of this programme, not a permanent feature-preview mode.

Retain P01’s single implementation, independent raw-record checker, full/descriptions portfolio, exact size selection, fixed-point behavior, and explicit work-limit rollback. No-op, size rejection, and explicit bounded-work exhaustion are not a disabled production mode. Normal defaults must not deliberately exhaust the budget to avoid P01, and required witnesses must finish under the shipping default. Statistics/diagnostics/budgets can remain grouped under a coalescing options record without reintroducing `Mode` or `.mode`.

Delete or keep deleted the public `off`/`safe` selector, old CLI arguments, manifest bypasses, environment switches, and generic enable-all/disable-all substitutes. Reject obsolete selectors rather than silently ignore or reinterpret them. There is no requirement to replace useful options-taking entrypoints with duplicate wrappers or rename current APIs solely for cosmetic consistency.

For historical comparison and one-pass attribution, use immutable predecessor artifacts/checkouts or narrowly scoped uninstalled test instrumentation. Never ship a retired compiler in a test directory, expose the comparison through normal public entrypoints, or make current expectations call the implementation under test. There are no 31 independent product booleans. Optional profile collection, genuine resource budgets, and P28’s offline solver tooling retain their distinct contracts; mandatory adoption does not mean running a solver, training a profile, or applying every rewrite on every input.

One existing options transport suffices for the standalone linker. No optimizer-policy fields enter BPI3/PST3/ABI. Qualified World acceleration is integrated into the one evaluator and preserves the exact image’s interruption/inspection/capacity contract; per-pattern eligibility and correct general cases remain necessary.

### 6.2 Establish a trustworthy baseline before transformation

The direct path must preserve this ordering:

```text
emit/build original source with original occurrence observations
    -> original source and named-capture obligations
       (or preserve their full evidence until the existing publication gate)
    -> lower original target
    -> original target admission
    -> existing qualified local normalization
    -> typed reachable baseline and applicable baseline checks
    -> selected new optimization pipeline
    -> independent transformation acceptance for selected rewrites
    -> final exact records with fresh applicable admission facts
    -> existing named-capture/publication gate, if originally outside lowering
    -> ordinary encoding
```

This order does not demand checking an identical immutable object twice. Reuse a check already performed on the exact object with the same obligations. It does prohibit projecting away invalid declarations before their required original checks or returning a result before an outer typed-authoring rejection has been honored.

Keep mandatory capture observers separate from optional statistics. Compose optional callbacks without replacing required observers. Preserve original occurrence identities through local caches and global sharing. Translate diagnostic locations through complete origin maps; do not pick the first constructor sharing a capture description and fabricate a unique source variable.

### 6.3 Dependency-aware semantic pipeline

Use this initial pipeline as the implementation baseline. Changes to ordering require a measured or correctness-motivated explanation, not a new architecture phase.

| Stage | Packages and purpose |
|---|---|
| Build efficiently | P17 and P30 preserve the checked source/record result while avoiding unnecessary construction work. |
| Establish facts | P02 and existing ownership, borrow, liveness, custody, and schema facts establish a sound initial analysis. |
| Simplify uses | P03, P04, P05, P07, P08, P09, and P10 remove known dispatch, unused arguments/captures, administrative aggregates, and local control closures. |
| Specialize effects and producers | P11–P16 apply only recognized handler, stream, hyperfunction, action, or context laws whose side conditions are established. |
| Optimize remaining control/data loops | P06, P18–P22, and P24 act on eligible regions using refreshed facts. |
| Search where justified | P27's bounded typed search and P29's controlled specialization operate on explicit eligible regions; P28 supplies separately qualified rules, not a compulsory compiler-time solver. P23 may guide candidate ordering and costs. |
| Normalize and share | Reapply shrinking local simplifications to a defined fixed point, always invoke P01 before closed-image publication, and use the existing final reachability/relocation/admission path. |
| Execute the selected image | P22's physical realization, P25, and P26 operate inside World with exact same-image behavior. |

The stages are not permission to reuse stale facts between packages. Record each pass's read/write domains; invalidate at least affected call summaries, CFG facts, demand/escape facts, and provenance when their premises change. Recompute sound facts before the next dependent transformation.

Code specialization may expose equal bodies, and sharing may reduce analysis precision. Keep code-equivalence identities distinct from analysis contexts. P01 remains independent and exact within its specified structural relation; do not insert an ad hoc merge into an inliner or e-graph extractor.

A shrink-only normalization loop must have a declared well-founded measure or a proved normal-form property. Expansive specialization/search does not run in that loop without consuming a finite budget. Do not alternate inlining and outlining indefinitely. Final P01 has its own idempotent, exact-size selection contract; the entire bounded semantic pipeline does not claim globally optimal or universally idempotent output.

### 6.4 Open components and final closed linking

An open component is not a closed program. Preserve exports, import assumptions, nominal identities, checked borrow summaries, and all required original obligations. P01 remains deferred during open BMO1 emission and runs at final closed linking; there is no production toggle. Preserve independent evidence that introducing the closed-program pass does not alter open-component obligations. This does not claim that explicitly selected, contract-preserving semantic local optimization of an open component always leaves its bytes unchanged.

For semantic component compilation, use only facts valid under all admitted implementations of unresolved imports. Derive contextual summaries from actual declared contracts and bodies; unknown imports are not pure or total by default. Any private implementation change must still satisfy the original export/interface contract. Do not reduce that contract to what a particular current consumer happens to use.

At final link:

```text
independently decode/admit every BMO1 object
    -> resolve ordered instances and explicit nominal bindings
    -> check original imports, exports, and borrow/authority guarantees
    -> admit original closed linked target
    -> construct validated typed live baseline
    -> run the shared selected record optimizer
    -> validate actual rewritten records and derive final admission facts
    -> ordinary BPI3 encoding
```

The optimizer must work when the component sources, native emitters, Agent authoring modules, and World runtime are absent from the linking process. No source-name annotations or trusted new optimization summaries may be necessary for correctness. Packages that intrinsically improve host-side construction, such as P17, do not run on already built objects; report the layer accurately instead of claiming a linker optimization performed source construction work.

### 6.5 Agent propagation and policy audit

Forward the identical compilation selection through direct compilation, typed authoring, compiled-tool wrapper creation, and the final data-only link. A semantic selection at the outer Agent entrypoint must not disappear at an intermediate component wrapper; equally, a structural selection must not accidentally enable semantic transformations at final link.

Before migrating an Agent workload to the semantic contract, inspect its exact use of internal quantum, cancellation, speculative branches, resource quotas, approval steps, effect classification, and exact proposal binding. Preserve all business-level limits and authored control decisions. If a policy equates a particular internal step count with a security or billing limit, retain its original structural path until that policy has a separately justified semantic definition. Do not treat an optimization option as authority to alter business policy.

Use unchanged application authoring and unchanged environmental replies for before/after evidence. Do not add repeated emitters or dummy loops to a real workload to make a package appear useful. Synthetic opportunities are separate required tests.

### 6.6 World-derived plans, reuse, and ownership

World may derive private accelerated dispatch or physical-layout plans from a fully admitted immutable image. Verify each plan against that exact image and keep it with the relevant prepared owner. Restoring a checkpoint under the same image must not require a previously cached plan: reconstruct it safely or use the ordinary path.

Derived plans must not change canonical image bytes or become a second wire execution language. They must preserve all supported invocation modes. Test fresh, prepared, resident, explicit-step, quantum-limited, checkpoint-transfer, cancellation, and capacity-failure paths separately. A fast path that works only when there is no interruption must decline or materialize correctly when interruption is possible.

Retain original primitive/control semantics as the independent comparison path. Do not delete the only unaccelerated reference path before differential qualification is complete. After qualification, keep a practical test-only ablation rather than maintaining two independent interpreters.

Every returned record/plan owner must survive release of borrowed input buffers and scratch, and every failure path must release its allocations. No process-global mutable caches, raw pointers in portable state, hidden borrowed lifetimes, or dependency on allocator address identity are permitted.

## 7. Search, profitability, termination, and determinism

### 7.1 Correctness precedes cost

The decision order is:

```text
establish eligibility -> construct candidate -> validate correspondence/rule
    -> independently admit exact candidate -> measure static costs
    -> select or reject on profitability -> publish only selected owner
```

A proof search that cannot establish a candidate's preconditions returns `no_proof` without claiming a rewrite. Once a candidate is presented with a purported valid witness, failed validation or admission is an optimizer error, not an ordinary unprofitable candidate. This distinction must remain visible in tests and reports.

A legal rewrite is not necessarily a useful rewrite. Measure code size, capture retention, dynamic work, admission storage, and compiler cost separately. An environment summary may take more work to compute than it saves. Specialized code may be larger but faster. Shared code may worsen context-sensitive admission behavior. None of these tradeoffs changes the semantic proof.

### 7.2 Exact cost for P01; explicit objectives for other passes

P01 retains Annex A's exact BPI3 length and live-catalogue-count portfolio, fixed tie breaking, no-growth guard, and strict finite descent. Its baseline is the admitted input to that invocation of P01, even when earlier semantic passes have changed that input. Report original-to-final size separately so P01's local non-growth cannot hide earlier growth.

For the full semantic pipeline, use exact encoded bytes for image cost and explicit deterministic estimates for dynamic cost when no valid profile is present. The estimates are heuristics, never claimed measured runtime. Count the actual shared graph and actual encoding; an e-graph expression-tree cost or sum of estimated per-merge savings is not the final program cost.

The following are proposed default **image-growth budgets**, not observed performance results:

| Objective | Maximum final BPI3 growth over the same input's ordinary validated baseline |
|---|---|
| `size` | Zero bytes. |
| `balanced` | `max(1024 bytes, ceil(0.05 × baseline_bytes))`. |
| `speed` | `max(4096 bytes, ceil(0.25 × baseline_bytes))`. |

A caller may provide an explicit byte budget. Zero is meaningful. Use checked integer arithmetic, not floating-point arithmetic that could round inconsistently near a threshold. An explicit budget does not override a hard application/wire limit. The compiler may select the unchanged baseline; none of the objectives requires growth.

These are extraction limits, not proof of economic qualification. A code-growing candidate needs evidence for its intended benefit before its rule/profile becomes a promoted choice. Do not raise the budget after seeing a failing benchmark merely to change the verdict. Any changed default is a documented prospective policy change with the full corpus rerun.

### 7.3 A small candidate portfolio, not exhaustive global search

Maintain at least the ordinary baseline and the current best completely validated candidate. A practical deterministic portfolio includes: shrink-only simplification; flow-driven specialization followed by shrinking; recognized algebraic/library fusion; and a profile-guided or bounded-search candidate when requested and available. Evaluate only paths whose packages are qualified for the selected contract.

Keep candidate history small and release rejected scratch immediately. Do not materialize every combination of 31 packages. Candidate selection may use a deterministic Pareto filter over exact image bytes and explicit operation/retention estimates, followed by objective-specific tie breaking. Define that tie breaking in code and tests. For example, `size` prioritizes exact bytes, then live code/description count, then fixed pipeline order; `speed` may prioritize validated profile-weighted cost within its hard byte budget. Record the actual strategy instead of presenting a heuristic as a global optimum.

The program-wide candidate remains the unit of final cost acceptance. Independently profitable-looking local rewrites can interact through code sharing, compact IDs, admission joins, and capture lifetimes. Recompute final exact cost after normalization/relocation. P01's parent/child congruence restrictions remain enforced when its extraction portfolio retains distinctions.

### 7.4 Finite analyses and bounded searches are different

Sound analyses must reach a fixed point or a checked post-fixed point before their facts authorize a rewrite. Use finite domains, monotone transfer functions, and explicit widening where necessary. Exhausting a budget must not publish an unfinished optimistic constructor set, range, escape fact, or coalescing partition.

Search may stop with a previously validated incumbent. Count deterministic work units such as transfer applications, exact comparisons, generated candidates, e-nodes, or driven specialization states. Specify checked limits on memory and generated code as well. Wall-clock time may be reported but must not select different default output on repeated identical inputs.

On budget exhaustion:

- P01 obeys Annex A exactly: roll back that P01 attempt to its original validated input, including abandoning intermediate P01 extraction rounds.
- Other candidate searches may retain the last fully validated candidate or ordinary baseline. The incomplete candidate and its facts are discarded. Report which work was skipped.
- If a required acceptance fixture exhausts the shipping default budget, the package has not met its delivery requirement for that fixture.

Allocation failure, checked size overflow, malformed references, false proofs, and violated optimizer invariants are errors. They are not disguised as budget exhaustion or `no_change`. A caller choosing a small optimization budget is distinct from a malformed program or broken implementation.

### 7.5 Prevent specialization and rewrite cycles

Memoize specialization by the full relevant static contract and static values, with deterministic canonical keys. Reuse a specialized worker already constructed for the same key. Never key by incidental host pointer or source emitter name alone.

Use one of the proved controls specified in P29 for growing static configurations. When embedding/generalization triggers, residualize the dynamic distinction without losing it. Reject an invalid generalized worker instead of accepting a widened semantic guess. Maintain a finite set of canonical candidate identities so inlining/outlining or reassociation cannot repeatedly rediscover the same program within one search.

An e-graph may be cyclic, but extracted executable code must obey the existing IR's explicit recursion/control forms. A cycle in an equivalence graph is not a recursive function definition and cannot justify a zero-cost self-extraction. Nonnegative extraction costs and a finite well-typed witness are required.

### 7.6 Reproducibility, profiles, and no-op behavior

For identical admitted input records, policy, toolchain, rule set, and profile bytes, compilation/linking must produce identical selected bytes and outcome categories. Optional observers must not affect output. Hash collisions and randomized bucket iteration must not affect correctness or representative selection.

Profiles are optional evidence about workload frequency, not semantic truth. Bind them to exact identities and validate mapping before use. Reject or explicitly disregard stale/incompatible data. Keep unknown/rare paths correct. The same validated profile and options must yield deterministic compilation even if runtime timing differs during another run.

A semantic pipeline need not be idempotent across repeated invocations with freshly reset search budgets unless that property is explicitly implemented. Report it as a bounded optimizer, not a universal normalizer. P01 still must be idempotent under its own contract. On a genuine no-op, preserve the ordinary baseline representation rather than churning IDs for cosmetic normalization.

## 8. Validation and mandatory acceptance matrix

### 8.1 Package-level completion tests

## 9. Measurement, promotion, and regression policy

### 9.1 Controls and attribution

### 9.4 Reproducible timing and significance

For each timed cell, use at least three independently launched alternating control/optimized windows, each process with at least three warmups and nine measurements, unless an existing stronger qualified harness specifies otherwise. Record paired window medians and enough raw data to reproduce the report. Separate cold, prepared, and resident execution; use the same capacities, inputs, replies, optimization level, machine, and toolchain within each pair.

A suspected regression requires two additional alternating confirmation windows. A timing regression greater than 5% is reproducible under this protocol when the median paired ratio across all five windows exceeds `1.05` and at least four of five individual window ratios exceed `1.05`. Report variance and inconclusive cells honestly. Do not select the best sample, aggregate away a failing workload, or infer statistical confidence from a single run.

For P23, freeze training/profile inputs before evaluating held-out workloads. Profile collection cost is reported separately. A specialization that works only on its training trace has not demonstrated robust value; rare paths must remain correct even when they are slower.

### 9.5 Economic and promotion gates

These thresholds are inherited engineering acceptance criteria from the supplied programme, not newly measured results. P01’s structural correctness and exact no-growth gates remain mandatory; its former minimum real-consumer gain and optional-default promotion gates are retired. Apply timing/memory/checkpoint thresholds to costs actually incurred by World or its workload. Explained Boundary-only construction/checking/lowering/emission costs follow Part I’s accepted-regression policy. For canonical qualified packages, use the following policy:

| Dimension | Promotion requirement |
|---|---|
| Correctness | All package and applicable cross-package checks pass; each selected rewrite has its production acceptance mechanism. |
| Demonstrated capability | Minimum positive witness actually removes the targeted cost; negative witnesses remain correct. |
| Real-consumer claim | Any claimed Agent benefit is measured on unchanged current applications. A package with only synthetic value is labeled accordingly. |
| World execution/admission timing | No reproducible greater-than-5% slowdown in a required World-side cell without targeted correction or an explicit separately accepted tradeoff. Boundary-only compiler/admission measurements do not inherit this cap. |

Within-threshold regressions still appear in the report. Retain qualified capability in the canonical pipeline and make candidate selection economical; a mathematically legal rewrite need not be selected. Do not deliver required packages as permanent experimental/opt-in products. An unresolved material World regression remains an explicit acceptance decision, not a hidden legacy fallback. A missing real-Agent opportunity is reported honestly and does not undo the accepted P01 adoption decision. Boundary construction costs alone do not reopen promotion.

Do not reinterpret a prior accepted workload cost as a new defect merely to restart architectural work. Record existing accepted tradeoffs at C0. This programme must not silently introduce new ones or claim prior improvements as its own. Explicit tradeoff acceptance, where needed, belongs to the implementing session's actual authorization; the spec does not preapprove arbitrary regressions.

## 13. Observation-closed representation synthesis

**Version-2 normative extension to P02, P07, P09, P15, P27, and P31.** This section strengthens the existing packages; it does not replace the 31-package programme with a new project or introduce a second optimizer. All earlier capabilities, P01/Annex A constraints, and correctness/economic gates remain required. The implementation must derive a representation for a supported class of stateful computations, not hardcode the examples below.

The concrete deliverable is a source-independent, certificate-checked synthesis pass for **private affine bitwise state**, integrated with capture/worker rewriting and closed linking. It computes the information sufficient for every future supported observation, not merely the fields read by the next instruction. A finite reference implementation and independent tests are included in Annex C. They validate a mathematical fragment, not production Boundary extraction, emission, ownership, or performance.

### 13.1 The substantive change: synthesize the state, not only simplify its uses

P07 already requires sufficient environment summaries, and P15 requires compact representations of pending actions. A separate handwritten summary law for each generated state machine would leave substantial capability dependent on anticipating each source shape. The new mechanism must solve a precisely delimited synthesis problem:

```text
Given the checked operations that update a private environment,
and every operation allowed to observe it,
find a smaller representation closed under those updates and observations.
```

Syntactic liveness does not answer this question. All fields may participate in every iteration while only a lower-dimensional combination of them influences behavior. Likewise, a summary that reproduces the current return value may be inadequate after a later update. Candidate discovery must include both facts.

The connection to established mathematics is deliberate. Environment/evaluator factorization supplies the representation question; observability supplies closure under future evolution; coalgebraic reasoning supplies a behavioral quotient; finite-field algebra makes a useful fragment exact and checkable. These are established ideas, not a claim that this document invents observability or proves a new general adjoint-functor theorem. The design contribution specified here is their application to Boundary's checked captures, stable-slot transfers, control locations, source-free linking, and observation contracts. [N1] [N2] [N3]

### 13.2 Declare the observer before optimizing its representation

An **observation boundary** is a use whose required value or behavior must survive a representation change. The optimizer does not get to choose which inconvenient observations count. The existing application/compiler contract determines them.

For an eligible private slice, census every outgoing use: return values; effect payloads; branch predicate operands; values passed to unresolved consumers; exports; captured data that escapes; cleanup or borrow dependence; and any original-state materialization promised by the selected contract. Include every supported continuation/resumption path that can reach such a use. A raw word not used in an ordinary result may still be needed by an escaped closure or a branch guard.

Distinguish three different forms of observation:

| Observer | Consequence for this pass |
|---|---|
| A known total expression of private scalar state | Seed that expression's exact affine rows when supported. |
| A consumer that requires selected original fields | Seed those coordinate projections; the summary must reconstruct them. |
| An opaque whole-state consumer or a same-image snapshot requiring all original scalar coordinates | Seed the identity matrix at that location, or decline the slice. |

Branch choice is observable control. The initial implementation preserves the existing branch and computes its operands exactly from the summary; it does not discard a predicate because a profile saw only one outcome. For a nonlinear comparison of affine operands, retain the comparison outside the affine slice and seed the affine operand rows. A genuinely unsupported state-dependent computation forms a boundary, rather than being silently linearized.

Keep authority, ownership, identity-bearing objects, and control tokens in their original checked representations. The affine state may be a private scalar component of a larger environment, but the transformation must prove that its boundary values and rewritten use graph preserve the surrounding obligations. It must not make a resource-bearing field disappear by treating its bytes as an integer vector.

### 13.3 The general obligation: a summary must be stable under future use

For a total deterministic state machine with state `s`, a permitted action/input `a`, an observation `out(s,a)`, and a next state `step(s,a)`, a summary `h` is sufficient only when reduced operations satisfy:

```text
out(s, a)       = out_reduced(h(s), a)
h(step(s, a))   = step_reduced(h(s), a)
```

The initial reduced state must be `h(initial_state)`. By induction over action sequences, these two equations preserve every finite observation trace. In this total, one-transition-for-one-transition model, they also preserve whether a given infinite action sequence continues indefinitely. They do not prove progress or divergence of an arbitrary effectful source computation; extraction/emission still need the Section 4 simulation argument.

The second equation is essential. Let the only immediate observation of `(p,q)` be `p XOR q`. Swapping the fields preserves a one-word summary. Adding an update `(p,q) -> (0,q)` invalidates that summary: `(0,0)` and `(1,1)` initially have the same observation, but after reset their observations differ. A present-output matcher would wrongly merge them; update closure must retain the extra distinction.

The mathematical kernel of a valid summary is a behavioral congruence: states with equal summaries have equal observations and successors with equal summaries for the same action. For finite machines, partition refinement can compute the coarsest such relation, and a pair search can supply a distinguishing future suffix for an invalid proposed merge. Those procedures are useful independent finite test oracles. Production Boundary state is not generally finite and small enough to enumerate; the next section gives a compact exact symbolic fragment instead. [N3] [N4]

### 13.4 Eligible affine bitwise fragment

The first production recognizer MUST support a private tuple of `n` equal-width unsigned integer words of width `w`, with every rewritten data operation drawn from a checked subset of current records. State can be explicit worker parameters, a private product, or closure captures connected through known constructor/call uses. All uses of the rewritten representation must be covered.

Support word moves, constants, XOR, statically typed product/field assembly, and known parallel transfers. Bitwise NOT may be represented as XOR with the all-ones constant after its actual primitive semantics is checked. Lower the result to existing word primitives and existing program/control records. The inspected `program.zig` has unsigned scalar schemas and `integer_bit_xor`, products, fields, and computations; this is evidence that the required basic representation vocabulary exists, not proof that a production recognizer or ABI rewrite is already implemented. [B10]

The minimum fragment excludes checked addition/subtraction/multiplication, shifts, conversions between widths, AND/OR of two dynamic values, arbitrary integer comparison as a linear output, mutable aliasing, lazy forcing, resources, and native Zig execution. In particular, the inspected opcode list does not provide a general shift primitive; do not introduce one to make the analysis appear broader. Dynamic AND is not linear over GF(2). A separately proved constant mask transformation is a possible later bit-level extension, not a reason to include dynamic AND in this word-coordinate implementation.

For a control transition `a`, use the exact model:

```text
x_next = A_a x XOR B_a u XOR c_a
y      = O_a x XOR D_a u XOR e_a
```

Here `x` is the old private word tuple, `u` is the ordered tuple of independently supplied dynamic word operands, and `y` lists the required affine observations. The matrices have coefficients in `{0,1}` and act on whole words by XOR. Constants `c_a` and `e_a` are word tuples. This is a vector-space/module calculation over bit lanes, not integer arithmetic modulo a power of two and not multiplication in a newly introduced extension field.

All source operand computations supplying `x` and `u` retain their original evaluation/demand/failure order. The transformation concerns the already-available scalar dataflow. Every modeled action is total inside the selected slice; side effects, potentially failing work, handler operations, user yields, and ownership transitions remain explicit boundaries outside it.

A branch whose coefficient matrix depends on a runtime condition may be represented by a finite set of checked alternatives, preserving the original branch. Prove coverage and exact predicate reconstruction. The analysis may consider extra state-independent alternatives conservatively, but may not omit a possible update. Unresolved dispatch or an unknown writer forces a boundary or rejection.

### 13.5 Compute the least future-observation row space

For a single control location, let `W0` be the span over GF(2) of every row of every observation matrix. Iteratively close that space under each transition matrix:

```text
W0     = span(all rows of O_a)
W_next = span(W union { r A_a | r is a basis row of W; a is any action })
```

Stop only when the space is stable. A nonterminal step strictly increases rank; rank is bounded by `n`. Use exact bitset Gaussian elimination and dependency worklists. Do not use floating-point rank, tolerances, sampled inputs, or a profile-derived action set. A deterministic work limit may abandon the attempt, but it cannot publish a partially closed summary.

Let `H` have an independent basis of the resulting space as its rows, and let `r = rank(H)`. Synthesize reduced state `z = H x`. Closure permits matrices `F_a` and `J_a` satisfying:

```text
H A_a = F_a H
O_a   = J_a H
```

The executable reduced operations are:

```text
z_next = F_a z XOR (H B_a)u XOR H c_a
y      = J_a z XOR D_a u XOR e_a
```

The arbitrary dynamic input and affine offsets matter. A certificate for `H A = F H` alone is insufficient if input coefficients or constants are rewritten incorrectly. Do not derive a smaller captured state and then keep using the old update ABI.

This search derives the summary from matrices extracted from actual records. It MUST work on previously unseen eligible matrices, subject to documented budgets. Recognizing only a literal source pattern named `rotate` or `xor_accumulator` is not completion.

### 13.6 Exact certificate and proof boundary

A temporary certificate contains the original/reduced slice correspondence, dimensions, ordered input/output interfaces, `H` per control location, and the actual reduced matrices/records. Its acceptance checker MUST establish:

| Obligation | Required check |
|---|---|
| Extraction fidelity | Each original scalar definition, simultaneous transfer, observation, and boundary use is accounted for by the extracted affine expression or explicitly retained computation. |
| Action coverage | Every admitted incoming/outgoing control alternative and dynamic-input position is included in the proper order. |
| Matrix legality | Widths, dimensions, bit masks, constants, and row interfaces are valid and match the actual slice. |
| Output factorization | `O_a = J_a H`; direct input observations and output offsets are unchanged. |
| Transition closure | `H A_a = F_a H`; input term equals `H B_a`; state offset equals `H c_a`. |
| Initialization/conversion | Actual entry construction computes `H x` after the required original operand evaluations. |
| Emission fidelity | The actual emitted worker/capture/edge records implement the checked reduced equations and interfaces. |
| Surrounding semantics | Demand, failure, authority, custody, use, escape, control, and required materialization obligations are preserved. |
| Freshness | Original and replacement evidence belongs to the exact immutable record epochs being checked. |

The linear soundness calculation is elementary and should be part of the code-adjacent argument:

```text
z = H x

z_next
  = F_a z XOR (H B_a)u XOR H c_a
  = F_a H x XOR H B_a u XOR H c_a
  = H(A_a x XOR B_a u XOR c_a)
  = H x_next

J_a z XOR D_a u XOR e_a
  = O_a x XOR D_a u XOR e_a
```

Thus the relation `z = H x` is preserved and the required outputs agree. Bitwise semantics apply the same proof independently in every word bit lane. This is a width-parametric justification for the supported XOR fragment; testing four-bit values is not used as a substitute for that argument.

The matrix checker is not allowed to call the closure finder as its authority. Direct exact matrix equations suffice to validate the proposed representation even if discovery used a different basis or a nonminimal sound space. Minimality and profitability are separate questions. Sharing low-level XOR/matrix access helpers is acceptable; accepting the finder's conclusion without checking the actual candidate is not.

Three trust boundaries remain distinct: **IR to model**, **model to model**, and **model to emitted IR**. Annex C implements/checks the middle boundary only. A correct matrix theorem coupled to an incomplete use census or a wrong capture permutation is still a compiler bug. Production acceptance must cover all three.

### 13.7 A stronger minimum witness: three live words become two

Use three arbitrary runtime words `(p,q,r)` with observations and update:

```text
observe(p,q,r) = (p XOR q, q XOR r)
update(p,q,r,u) = (q, r, p XOR u)
```

All three original fields are syntactically live. Define:

```text
a = p XOR q
b = q XOR r
```

The derived representation is:

```text
observe_reduced(a,b) = (a,b)
update_reduced(a,b,u) = (b, a XOR b XOR u)
```

The unobservable difference is a common XOR applied to all three fields. It remains unobservable after every update for the same `u`. The quotient therefore needs two word coordinates, not three. This is not deleting an unused field or sharing two identical function bodies; it changes the basis of the retained information.

The production positive fixture MUST use at least one private capture/worker cycle so that representation rewriting crosses a callable interface. A pure arithmetic expression test alone does not demonstrate capture-state synthesis. Initialize the original three words at runtime; exercise multiple successive updates and observations, separate instances, and a source-free linked construction. Prove all original uses and capture-bound obligations accounted for.

Acceptance requires reducing the eligible private representation from three words to two while preserving the observations for all inputs under the supported fragment. It does not require, or promise, a 33% whole-program memory improvement. Headers, retained control, temporary initialization values, surrounding captures, alignment, and analysis costs can dominate the two-word payload.

Also implement the scaling family in which `n` live words are permuted and one coordinate receives XOR input while the only permitted scalar observation is the XOR of all coordinates. The derived scalar summary has one word. Test `n = 2, 3, 8, 32, 64, 128`, including a generated permutation not named in the matcher. Initialization still consumes the original input words; constant-size retained summary is not constant-time initialization or a claim that the entire program uses constant space.

### 13.8 What is minimal, and what is not

For the exact single-location affine machine where every action is permitted independently of state and the initial domain is the entire vector space, the computed row space consists of the span of all future observation functionals. Its kernel is the largest subspace whose differences remain unobservable under every action sequence. For the location-indexed case below, use only control-valid paths from the relevant location.

The minimality argument is:

1. Every immediate observation must factor through a sufficient linear summary `G`.
2. Preservation through every update requires every future observation row to lie in `rowspan(G)`.
3. The construction of `H` generates exactly the least space containing those rows and closed under their predecessors.
4. Therefore `rank(G) >= rank(H)`, and the constructed `H` attains that bound.

Equivalently, two full-domain states are indistinguishable by every allowed future observation exactly when their difference lies in `kernel(H)`. For binary scalar states this gives `2^r` behavioral classes. Any finite lossless representation of those classes requires at least `r` bits in the worst case, irrespective of whether its encoding is linear. With `w` independent fully observable word lanes, the analogous class count is `2^(r*w)`. This counting statement assumes that the representation has no hidden external store carrying the discarded distinctions.

These are deliberately restricted optimality claims. They do NOT establish the smallest BPI3 image, fastest instruction sequence, smallest resident/checkpoint allocation, minimum reachable-state representation under extra input invariants, or globally optimal Boundary program. With state-dependent guards conservatively overapproximated by extra actions, the resulting summary is sound but may be larger than the minimum for actual executions. With a restricted reachable domain, fewer distinctions may suffice; exploiting it requires a separate checked reachability/invariant argument.

An output-only checker cannot establish minimality. A full-rank identity summary is sound but may be unprofitable. The independent finite-state oracle in Annex C checks both directions of equivalence on its finite test cases; it does not turn those samples into a general production minimality proof.

### 13.9 Different control locations can have different sufficient states

Do not require one global capture layout when different points need different observations. Let location `l` have original dimension `n_l` and summary matrix `H_l`. An edge `a: l -> m` has:

```text
x_m = A_a x_l XOR B_a u XOR c_a
y   = O_a x_l XOR D_a u XOR e_a
```

Seed the local observation rows, then propagate successor requirements backward:

```text
W_l := span(local observation rows)
repeat to stability:
    for every edge a: l -> m:
        W_l := span(W_l union { r A_a | r is in a basis of W_m })
```

A strict change increases total rank, bounded by `sum_l n_l`. The reference algorithm may rescan; the production implementation should use predecessor worklists. It must not unfold recursive execution or assume that numeric stable-slot IDs identify globally immutable values.

The local certificate replaces the global closure identity with:

```text
H_m A_a = F_a H_l
O_a     = J_a H_l
```

Input and affine terms use `H_m` for next state, and initialization/conversions use the exact local interfaces. Lower each accepted layout to the existing function/capture/slot forms. No dependent-type wire extension or location-indexed runtime is required. If current constructors/interfaces require a fixed arity across a use family, specialize eligible private workers or retain the shared full layout; do not weaken callable schemas.

**Required placement witness:** a first location exposes both original words, then enters a loop that only observes their XOR and swaps them. The first location needs two coordinates; the loop needs one. Adding a legal edge back to full inspection must propagate the two-coordinate requirement back into the loop. Merely recording that inspection happened earlier is not sufficient if it can happen again.

The uniform whole-SCC algorithm may be delivered as an early slice. The completed synthesis extension must include this control-location-sensitive case and source-free linking. It does not have to identify every possible maximal slice or minimize all simultaneous layout choices globally.

### 13.10 Materialization is an information requirement, not a bookkeeping flag

For linear summaries, an original projection `M x` can be reconstructed from `z = H x` for all original states precisely when there is a matrix `T` with:

```text
M = T H
```

The forward direction constructs the decoder. For necessity, equal summaries must imply equal projected values, so `kernel(H)` must be contained in `kernel(M)`, equivalently the projection rows must lie in `rowspan(H)` over the field.

For full original-state reconstruction, `M = I`. A rank-deficient `H` alone cannot provide that reconstruction. There is no valid deoptimization or checkpoint shortcut that recreates genuinely discarded information merely by naming an original source location.

There are constructive alternatives, with different costs:

- Preserve only the required residual coordinates alongside the summary, and count their storage and update cost.
- Keep a representation rich enough until after the final relevant observer, then compress at a proved boundary.
- Recover from independently retained inputs or a permitted replay mechanism, accounting for every retained byte and preserving demand/effects; do not re-execute environmental operations as a recovery trick.
- Decline the incompatible rewrite and continue other optimizations.

The minimum implementation requires the second alternative and correct rejection when full reconstruction remains necessary. It does not introduce a general replay/deoptimization system. World same-image execution retains its exact checkpoint/quantum/inspection contract. The semantic compilation option still does not authorize transplanting old state into a new image.

A useful exact counterexample is a runtime XOR chain with masks `m1..mn`. If the contract permits observing every accumulated prefix `p_i`, then:

```text
m1 = p1
mi = p_(i-1) XOR p_i, for i > 1
```

Those observations distinguish every mask sequence. At a cut where arbitrary such prefix observations must still be answerable, any self-contained summary needs enough information to distinguish `2^(n*w)` sequences in the worst case. If only the final XOR matters, one word suffices. The lower bound assumes no retained original sequence, input transcript, or other hidden information source; retaining one can permit reconstruction but must be counted. An online executor that has already delivered earlier prefixes need not store them solely to replay observations the API never promises.

This distinction explains why semantic compilation can remove private state while same-image acceleration may only reduce the cost of executing/materializing it. Do not impose the stronger observer on every application, and do not remove it from an application that requires it.

### 13.11 Separate quotient discovery from coordinate and placement economics

A smallest-dimensional state space can have several bases with different computation costs. A canonical reduced-row-echelon basis is convenient for discovery and equality; it is not automatically the cheapest representation to construct, update, observe, encode, or admit.

For the three-word witness, taking the two output rows themselves as the basis gives direct output projections. Another equally ranked basis may require extra XORs to reconstruct the same outputs. The implementation MUST accept independently checked invertible coordinate changes and evaluate at least these deterministic candidates when distinct:

1. The canonical elimination basis.
2. An ordered independent basis favoring existing observation expressions, extended with required transition images until it spans the same closed space.
3. The unchanged original representation.

This is a small portfolio, not an enumeration of the general linear group or a promise to minimize all XOR circuits. Candidate generation may reuse P27 to simplify pure entry/update/output expressions. Basis changes must preserve the matrix identities and the complete slice relation. A matrix with fewer nonzero entries is only a heuristic for instruction cost; shared subexpressions, retained values, and actual record encoding still matter.

Compare full candidate materializations with the existing objective and exact BPI3 budget. Include entry conversion, exit reconstruction, worker specialization, capture descriptors, transient live values, and repeated boundary crossings. A two-word summary that needs expensive reconstruction at every use may be worse than the original three words. Profiling may guide this choice, but the observer/action set and soundness certificate are profile-independent.

Allow different valid representations in different slices only when conversions are checked. For summaries `H_from x` and `H_to x`, a scalar-only conversion exists when `H_to = T H_from`; the reverse need not exist. Where other retained data is used, include it explicitly in the source of the conversion and its cost. Cyclic placement uses a deterministic bounded portfolio and checked interfaces, not a claim that a local greedy choice solves the global placement problem.

### 13.12 Counterexamples and nonlinear generalization

The production affine checker can identify an offending missing row or failed matrix equation directly. For small finite models, the independent behavioral oracle MUST provide a concrete future action suffix when a proposed state identification loses information. The reset example must distinguish an initially equal-output pair after a later update; a counterexample only to immediate output is insufficient.

Use these failures to refine the recognizer, observer census, or candidate summary. Do not fix them by discarding an action from the model, by trusting an observed profile, or by weakening the required output comparison. An invariant violated by the actual program is not an optimization opportunity.

For nonlinear finite state, closure can be considered on observables `f` under precomposition `f -> f o transition`. On a finite state set, this yields a finite function space, but its dimension can be exponential in a compact original encoding. A linear realization in that enlarged space is not automatically a smaller state representation, and minimizing its linear dimension is not the same as finding a minimum Boolean encoding of the behavioral classes. [N2]

P27/P28 may explore such finite fragments using bounded truth tables or exact symbolic laws, and the finite-state oracle can validate small examples. This revision does not require embedding an exponential Koopman realization engine into ordinary compilation. The mandatory new production synthesis subset is the affine fragment and its location-sensitive form. Unknown or nonlinear cases retain their original representations unless an already specified and separately checked transformation applies.

### A.4. Semantic model and correctness obligation

#### A.4.1 Typed coproduct interpretation

For a checked callable contract `S`, view its defunctionalized values schematically as:

```text
Closure[S] = Sum over c in Constructors[S] of Environment[c]
```

A constructor identifies code and a compatible environment layout. A closure value supplies a particular environment instance.

Coalescing establishes an equivalence relation on eligible code/descriptions and a quotient map `q`. For equivalent constructors with the same ordered capture interface:

```text
q(ConstructorA(environment)) = Representative(environment)
q(ConstructorB(environment)) = Representative(environment)
```

The environment is preserved. It is not interned with any other environment.

The required semantic law is:

```text
execute(P, input, replies)
    is behaviorally equivalent to
execute(optimize(P), input, corresponding replies)
```

Equivalence is defined below. This specification does not claim to produce the smallest possible program or decide every pair of behaviorally equivalent functions. It requires complete discovery of the eligible finite structural relation in Sections 6–8. Materialization may retain extra cases only under the specified identity restrictions, candidate profiles, work limit, or exact cost-selection rules. Report what was proved equivalent separately from what was physically merged.

#### A.4.2 What must be preserved

For admitted input and corresponding environmental responses, the transformation MUST preserve:

| Dimension | Required preservation |
|---|---|
| Ordinary computation | Results, failure payloads, branching, termination/divergence behavior, and arithmetic/primitive semantics. |
| Effects | Operation identity under an injective nominal relocation; payloads; operation-body order; use-site evidence; handler selection; residual effect contracts. |
| Evaluation order | Operand and instruction order, failures, cleanup, and externally observable requests. |
| Control | Direct calls, applications, returns, yields, deep/shallow handling, answer transformation, suspension, resume/dispose behavior. |
| Ownership and borrowing | Affine/linear/multi/reusable distinctions, capture bounds, region lifetimes, borrowed paths, custody scopes, and cleanup establishment/unwind order. |
| Mutable state | The original aliasing and separation relationships between dynamic nodes; branch-local mutation and multi-shot semantics. |
| Authority | Nominal effects/regions/resources and the function-identity relationships that grant introducing/eliminating rights. |
| Logical execution boundaries | The same existing logical operations at matched stepping/work-quantum boundaries, modulo static reference relocation. No extra wrappers or hidden execution steps. |
| Agent protections | Classification, speculative restrictions, approval, exact-proposal binding, and execution/commit policy as enforced by the unchanged authoring/admission/runtime contracts. |

Image bytes, static catalogue IDs, program hashes, hash-bound request/checkpoint envelopes, and diagnostic representative choices may change. They are not compared for equality across different program identities. This exception does not permit weakening nominal distinctions, payload comparison, custody, or authentication.

Wall-clock time and physical memory consumption are measured, not asserted identical. Semantic comparisons run with adequate capacity; resource-limited execution retains valid capacity/error behavior and must not corrupt state. Any change to an existing contractual work counter or semantic quota is a defect, not a performance gain.

#### A.4.3 Preserve admission precision as well as behavior

The shipping compiler/linker MUST NOT narrow the previously supported valid-input domain merely because coalescing joins code identities. A merge can be behaviorally sound yet unsuitable for a particular admission analysis if that analysis uses function or constructor identity to keep borrow/provenance facts separate.

Audit those dependencies. Preserve necessary analysis distinctions in eligibility or reference labels, or conservatively keep the affected classes separate. Any such exclusion must be justified by the actual admission rule and recorded; do not use a blanket prohibition on effectful code as a substitute for this work. Do not weaken ownership/borrow validation or replace an exact guarantee with a permissive union to recover a merge.

Add a fixture with equivalent code reached from distinct caller/provenance contexts. Both modes must continue to admit the valid program and reject its invalid counterpart. An unexpected candidate-admission failure is an implementation failure to investigate, not a clean run or silent optimizer success.

#### A.4.4 A state relation, not state rewriting

For the correctness argument and tests, relate executions by mapping static references through the optimizer's correspondence maps. Dynamic nodes correspond one-to-one between matched runs, preserving sharing and separation. A closure can refer to representative code while retaining its own capture values; two activations of representative code remain two activations.

This relation is a proof/test device. It MUST NOT be exposed as a saved-state migration feature. It must not alter, re-sign, or transplant a checkpoint into a different program merely to make a test pass.

#### A.4.5 Admission is necessary, not sufficient

The original program and all applicable original component obligations MUST be checked before this new pass can erase distinctions. The output MUST independently pass full closed admission and derive fresh flow/ownership/borrow facts.

A valid output is not by itself evidence that the optimizer preserved behavior. Acceptance also requires production structural correspondence validation, negative tests, and differential execution against the disabled path and independent semantic fixtures. Discovery may be sophisticated; the acceptance of a proposed rewrite must not rely on trusting discovery's own equality verdict.

#### A.4.6 The commuting-reference obligation

A first-order record graph permits a finite correspondence check. For a proposed map `q` from original live nodes to representative nodes, the essential conditions are:

```text
q(q(v)) = q(v)
local_label(v) = local_label(q(v))
q(target(v, role, position)) = q(target(q(v), role, position))
```

The labels here contain every non-reference semantic field, including kind and ordered arity. Anchors are fixed or injectively relocated as specified in Section 5. Function bodies additionally require the complete block/slot/custody bijections from Sections 6–7. Equality of labels is not permission to omit effect, failure, capture, or authority information.

The checker must also compare these originals with the **actual emitted candidate**, not merely establish that a correct candidate could be constructed. A correct map plus a buggy rewriter is still a miscompilation.

A correctness argument must discharge four obligations against Boundary and World:

1. **Initial states correspond.** Roots, input values, initial custody, and nominal anchors have the required relation.
2. **Each operation respects the correspondence.** Mapped instructions and control operations make matching transitions, preserve failure/effect/cleanup behavior, and relate their successor states without adding execution steps.
3. **Dynamic identity is preserved.** Existing node aliases remain aliases; distinct live instances remain distinct. Static code sharing is not a many-to-one map on dynamic objects.
4. **Observations and continuations correspond.** Outcomes, requests, yields, work boundaries, and resumed executions retain the contract in Section 4.2. Matching finite prefixes of an infinite execution are evidence only for those prefixes.

The graph laws provide a checkable structural foundation; they are **not** by themselves a mechanized proof of all Boundary/World semantics. In particular, a hidden dependence on declaration identity defeats a naive renaming argument. The identity audit and opcode-by-opcode argument must establish why the allowed maps preserve those semantics. Unknown cases are excluded or rejected, not presumed harmless.

#### A.5.1 Fixed nominal anchors

The pass MUST keep distinct effect declarations, nominal regions, and resources distinct. Only existing explicit component bindings may establish equality before the pass. Equality of names, payloads, representations, use modes, or enclosing components does not authorize additional unification.

Structural schemas referencing these identities may merge only when they reference the same already-resolved anchors. Nominal references are never alpha-renamed between candidate functions to make them match.

#### A.5.2 Pinned function identities

Every function appearing in any resource's introducer or eliminator authority set in the **validated typed live baseline** MUST be a singleton equivalence class. It MUST NOT merge with another privileged function or an unprivileged one, and no unprivileged function may be redirected to it by code coalescing.

Original declarations, including otherwise unreachable authority declarations, remain subject to their original checks before projection. After the established closed-world projection removes a genuinely unreachable resource, its discarded authority list does not create a hidden, history-dependent pin on an otherwise live function. This distinction keeps closed-record optimization reproducible and idempotent without retaining a new private authority-history format. Any identity with an actual external or remaining authority use must instead be part of the live roots/reference closure and remain pinned. This is not permission to prune open-component exports or an authority reference omitted by an incomplete traversal.

The entry function MUST also remain a singleton for this version. This conservative exclusion makes entry provenance straightforward and does not prevent sharing its generated callees.

Any additional identity-sensitive function reference discovered by the audit MUST receive the same treatment. This is not permission to pin all functions: required positive fixtures must still merge, and the final report must enumerate meaningful exclusions.

Pinned function bodies still require ordinary typed relocation when global descriptors change. “Pinned” means the equivalence class is singleton, not that its numeric output index or references can never change.

#### A.5.3 Other identity-sensitive descriptors

A handler or constructor description may merge only when the audit establishes that its static identity is descriptive under full relocation, rather than a token whose distinctness affects behavior. Imported/exported references and borrow projections must already have been discharged or be correctly relocated and rechecked.

A descriptor that remains externally identity-sensitive is a singleton. Its underlying unprivileged function may still share code only when descriptor separation and the exact callable ABI remain intact.

Raw inspection can expose new static IDs for a new program. It must still describe that program accurately. Do not falsely preserve a disappeared source site or conflate different runtime objects in the inspector.

#### A.5.4 Runtime identity is not available for merging

Sharing an immutable capture description does not share a capture payload. Sharing a thunk implementation does not memoize its result. In particular, two call-by-need thunks using the same representative code retain separate memo cells unless the original program already shared that same dynamic cell.

Two closure constructions with equal captures must still obey the original construction/allocation/identity semantics. This pass does not introduce common-subexpression elimination of construction instructions.

### A.6. Required equivalence rules

Equivalence is typed and exact after approved reference mapping. Do not substitute compatibility, subtyping, equal machine width, empty effect rows, or successful admission for equality.

#### A.6.1 Schemas

Reuse or factor the existing linker's finite structural schema partitioning into code usable by both paths. Preserve its nominal anchors and guarded-recursion requirements. Do not add a competing type-equivalence engine.

Schema labels include every primitive kind, bound, length, enumeration tag, internal kind, callable/resumption contract, usage mode, handler mode, obligations flag, and ordered/set-valued relationship specified by the existing records. References to other schemas are compared by established schema classes; references to nominal entities are compared by fixed anchors.

Ordered parameter, product-field, sum-variant, handler/evidence, and other ordered lists retain arity and order. Only fields already defined as sets are sorted/deduplicated after relocation. In particular, mapping the two branches of `sum(A, A)` to the same schema ID must still leave a two-element branch list.

No external value schema or wire interpretation may be changed by weakening a bound, collapsing a variant, changing a primitive width, reinterpreting bytes, or erasing an internal/public distinction.

#### A.6.2 Constants

Literal equivalence requires the same final schema class and byte-identical payload. Distinct schemas with equal width or equal bytes are not sufficient. Canonical constant encoding remains the codec's responsibility.

Only immutable literal records merge. Evaluation of an instruction that refers to a literal is not removed by this pass.

#### A.6.3 Capture descriptions

A capture description is equivalent only when its ordered field-schema list, use mode, owned regions, borrowed regions, and all other present fields agree after approved mapping. Region sets obey existing set semantics; fields retain exact order.

Capture permutations and environment adapters are out of scope. Matching two descriptions does not authorize dropping unused-looking fields or copying a linear capture.

#### A.6.4 Functions

Two non-pinned functions may share a body only when their complete normalized comparison views agree, including:

- Ordered input positions and schemas, result schema, declared effects, and declared nominal regions.
- The full local slot layout under a consistent bijection, including slot reuse and unused slots.
- Custody-scope parent structure and every block's active custody scope.
- Entry block, local control-flow topology, ordered instructions, opcodes, destinations, operands, non-reference immediates, failure tables, and terminator fields.
- Every outgoing typed global reference, compared by fixed identity or the appropriate finalized equivalence class.

Function-local block, slot, and custody numbers are alpha-renamable only through total, consistent, kind-correct bijections. Input **order**, capture **order**, and branch/variant **order** are not alpha-renamable.

Stable slots are not assumed to be SSA values. Two read/write occurrences of the same original slot must remain occurrences of the same mapped slot, across the entire function. Simultaneous edge assignments must continue to read the predecessor view.

All supported terminators, including effect handling, protecting, region entry, suspension and resumption, must be compared field by field. No wildcard that ignores a difficult operation is permitted. Non-reference `immediate` values must remain literal; do not mistake field indices, variant ordinals, enum tags, or slot IDs for catalogue IDs.

#### A.6.5 Constructors

Two eligible constructors may merge only when their callable-schema class, capture-description class, and function class all agree. Any additional constructor field in the selected revision also participates.

Two constructors may point at shared code while remaining distinct because their callable contracts differ. Such cases MUST retain their separate typed constructors. The optimizer does not erase contracts to increase the reported merge count.

#### A.6.6 Handler descriptions

Eligible immutable handler descriptions require equality of mode, input/answer schemas, state schemas, residual effects, return-function class, ordered clauses, clause effect identities, resumption schemas, strategies, and every other field.

Handler installations remain separate dynamic events with their original argument/state evaluation and custody. Deep and shallow handlers cannot match. A total-tail strategy is not interchangeable with a general strategy merely because both are admitted.

#### A.6.7 Blocks and other records

Blocks are not independently folded across arbitrary functions. Sharing a function retains one complete representative body; its corresponding duplicate blocks disappear with that body. The implementation must preserve block ownership and every retained incoming reference.

Do not merge two different blocks within one function as an additional tail-merging optimization. Existing jump threading remains a separate pass. Distinct resources and regions are never structurally interned. Data that is not explicitly covered by an equivalence rule is not eligible for coalescing.

### A.7. Comparison views and recursive equivalence

#### A.7.0 Validate everything required, then discover only live cases

Before this pass can discard evidence, run every original source, target, component, interface, authority, and borrow obligation required at that point in the existing path. An invalid unused declaration must not disappear before its required check. A source-specific publication check that currently consumes retained original evidence after lowering may keep that position, provided all of its original evidence is preserved and failure still prevents publication. Section 9.1 identifies the current named-capture case. The data-only optimizer does not replace or bypass the outer authoring admission boundary.

Next, establish the same typed reachable projection used by the disabled baseline. This is not a plain call graph: include every live schema, constructor, capture, handler, nominal reference, resource authority reference, and other reference traversed by existing reachability. Candidate discovery and representative selection operate on this live program. Check the projected program through the existing validation path or explicitly justified reuse of that path's checks; do not invent an unchecked input assumption.

This ordering separates two different responsibilities:

```text
all original obligations checked -> typed live baseline -> quotient discovery
```

Dead functions cannot become representatives solely because their original IDs are lower. Keep original provenance through the projection, but order representatives by the live baseline's established order. After a rewrite, project again to clean up records made unreachable by sharing. Attribute only this additional change to coalescing.

Reuse the existing reachable projection and its check, rather than adding a second reachability engine or retaining two redundant owned baselines. A caller-supplied naked record value is not proof that the required checks happened.

#### A.7.1 Normalize comparisons, not physical layouts

Build a deterministic comparison view for each function. It MUST ignore irrelevant local numeric names while retaining all semantics described above. It MUST NOT physically reorder the retained function's slots, instructions, assignments, or custody records merely to make the comparison convenient.

A suitable construction is:

1. Assign canonical input-slot names in call-interface order.
2. Discover the function's blocks from its entry using a deterministic traversal with successor positions in record-defined order: true before false, sum cases in variant order, and continuation edges in their specified positions. Preserve graph sharing and back edges with visited-node IDs.
3. Give each additional slot a canonical name at its first occurrence in the comparison traversal. Use that same mapping at every later occurrence. Process instruction and edge fields in a fixed documented order; this traversal order is not an execution rewrite.
4. Name custody scopes consistently with their parent structure, introducing ancestors before children and preserving the mapping at all uses.
5. Include all remaining layout slots and scope records through a deterministic completion. Unused slots can be paired by schema and multiplicity; unused scope subtrees can be canonically ordered by parent/shape. No ignored layout field is allowed.
6. Encode every field with an explicit kind, arity, and boundary. Global references become typed reference positions, not untyped integers or concatenated strings with ambiguous delimiters.

The input has already undergone the original validation. Blocks outside a function's executable entry closure may be excluded from its comparison view only as already-dead records, with their original validation obligations retained and ordinary reachability responsible for their removal. Do not infer that a branch is dead merely because a test did not take it.

Equivalent implementations may use a direct, exact graph comparison with consistent bijections instead of materialized canonical views. The resulting equivalence MUST be reflexive, symmetric, and transitive and MUST satisfy all required renaming tests. The production validator separately checks a proposed local bijection against raw records; it does not assume that comparison-view construction was correct. A pairwise “seems equal” heuristic whose result depends on candidate order is not acceptable.

Each successful function equivalence must supply enough local correspondence to map its blocks, slots, and custody scopes to the representative for verification and diagnostics. Retain the representative's original physical layout so existing slot-order optimizations are not undone.

#### A.7.2 Build a finite typed reference graph

After schema, constant, and capture equivalence is established, model eligible functions, constructors, and handler descriptions as a finite typed graph.

Each node has:

- A kind and a complete non-recursive local label.
- Fixed references, including nominal anchors and pinned identities.
- An ordered sequence of references to other eligible nodes, with edge roles and multiplicity.

A function's local CFG is represented in its comparison view. Cross-function calls, closure constructors, and handler-description references participate in the outer graph. This allows independently emitted recursive code groups to match without recursively expanding source types, control flow, or runtime environments.

#### A.7.3 Refine to a stable partition

The reference algorithm is exact partition refinement:

```text
partition := group by (node kind, local label, fixed anchors, pin identity)

repeat:
    refined := group by (
        previous class,
        node kind,
        exact local label,
        fixed anchors,
        ordered (edge role, target kind, target class) sequence
    )
    stop when the equivalence relation no longer changes
    partition := refined
```

Including the previous class ensures refinement only splits classes. Every nonterminal refinement increases the number of classes, which is bounded by the finite number of nodes. Compare equivalence relations or stable representative maps, not arbitrary temporary class numbering.

The implementation SHOULD use dependency tracking, worklists, SCC processing, or an established efficient refinement method to avoid rescanning unaffected nodes. It need not instantiate this reference algorithm literally. It MUST produce the same accepted relation for the required fixtures, and it MUST never merge using an unfinished optimistic partition.

Cycles are handled by the finite graph relation. Seeing a pair of nodes “in progress” is not by itself evidence of equivalence. A provisional recursive match must be discharged against every reachable labeled edge before publication.

This relation permits structurally bisimilar recursive code references when their full local operation sequences match. It does not permit inlining recursive calls, flattening stack depth, or replacing a two-operation loop with one operation. An otherwise matching group with one changed base-case constant or one changed effect must separate as refinement propagates the difference.

#### A.7.4 Restricting a quotient must preserve reference consistency

A materialization profile may retain distinctions that full discovery proved unnecessary. Such a restriction is not implemented by independently accepting or rejecting individual parent and child merges.

For example:

```text
F1 calls G1       F2 calls G2
G1 and G2 have identical implementations.
```

The full quotient may map `F2 -> F1` and `G2 -> G1`. A proposed partial map that retains distinct `G1` and `G2` but keeps `F2 -> F1` fails the commuting-reference condition of this specification. This is a failure of the specified structural witness; it is not a claim that every possible transformation sharing those parents is behaviorally unsound under a different proof relation.

To retain a class distinction, split the relevant class and refine predecessor classes until the relation is stable again. Never reuse a parent-equivalence witness whose referenced targets no longer correspond. Use the same finite refinement implementation, with additional singleton seeds for the restricted profile, and validate the resulting maps independently.

The mandatory materializations in Section 8 use only two fixed profiles. Do not build an exponential subset search, per-workload policy, or general profitability solver.

#### A.7.5 Hashing is an index, not a proof

Fingerprints may select candidate buckets. Exact typed comparison must resolve every hash match. Hash-table iteration, allocator addresses, randomized seeds, process history, and file paths must not determine output representatives or bytes.

Tests MUST force all fingerprints to collide and still obtain the same accepted equivalence classes and output as the ordinary implementation. Sorting by exact normalized keys is an acceptable alternative to hashing.

#### A.7.6 Deterministic work limits and error behavior

The implementation MUST terminate on every admitted finite input and respect existing allocation/admission limits. It MUST report actual comparison/refinement work. Avoid unbounded host recursion proportional to program depth.

An optional deterministic optimization-work limit is permitted to protect source-free linking. Its unit and default must be documented in the implementation report; the limit must count explicit work rather than wall time. It must not be tuned to particular benchmark names. No required acceptance fixture may hit it under the shipping default.

On that limit, abandon the entire optimization attempt, including any intermediate cost-selection rounds, and return the original ordinarily validated live baseline, with outcome `work_limit`. A fully processed input with the same deterministic budget must therefore remain reproducible. Do not publish a partially refined partition or count skipped work as completed optimization. This is a documented missed optimization, not malformed-program acceptance.

Allocation failure, integer overflow, invalid references, and a failed equivalence/relocation invariant MUST follow explicit error paths. They MUST NOT be swallowed as “no duplicates.” A failed post-transform admission is an optimizer defect/error and must not be hidden by silently falling back to the original program.

### A.8. Representatives, rewriting, and final selection

#### A.8.1 Representative choice

Within each finalized eligible class of a materialization profile, choose the lowest ID of that catalogue in the current, validated live program's established order. The original source provenance is retained separately. Never select an already unreachable original declaration as a representative. Pinned classes retain themselves. This makes choices independent of hash iteration and keeps output ordering explainable.

The promise is reproducibility for identical input records, options, and toolchain—not byte identity for arbitrary permutations of source declarations. Existing component instance ordering and binding rules continue to determine the link input order. Permuting a manifest's instance enumeration without changing keys/bindings must retain its existing deterministic result.

#### A.8.2 Typed maps

Construct explicit old-to-representative and representative-to-final maps for every relevant catalogue kind. Every live reference MUST map to a live object of the correct kind. A removed record may use the existing missing sentinel only when no retained reference needs it.

Mappings of retained nominal identities MUST be injective. Structural/code mappings may be many-to-one only as justified by the corresponding finalized equivalence class.

Use or extend the existing typed relocation machinery. Do not introduce a second independent, reflection-only integer remapper. Its mapping policy must cover:

- Roots, schemas, literals, effects, functions, blocks, handlers, captures, resources, and constructors.
- Call/apply/perform/handle/resume/protect/region operations and all nested edge records.
- Constructor immediates and constant/failure references.
- Resource authority lists, while keeping privileged functions singleton.
- Ordered fields versus true sets.
- Every applicable borrow-summary selector and provenance reference still used during checking.

Local slot numbers, custody numbers, field indices, variant indices, and other ordinals MUST NOT pass through a global ID map. When a duplicate function disappears, its local correspondence is separate from catalogue relocation.

#### A.8.3 Rewrite whole functions coherently

Retain each representative function and its complete representative body. Redirect code references to the chosen function classes. Keep the representative's original call-interface order and physical local layout. Map global references inside its body; do not combine blocks or instruction fragments from different candidates.

A duplicate function's entry/interior block correspondence must be valid for any static reference that is retained. Ordinary closed admission prohibits malformed cross-function edges; do not relax it to permit block sharing. If the selected revision has any legitimate extra incoming block-reference form, explicitly map it through the proved local correspondence.

Capture descriptions, typed constructors, immutable handler descriptions, schemas, and constants are emitted once per accepted class. Dynamic construction instructions and call sites remain in their original execution positions.

#### A.8.4 Apply the ordinary reachability projection

Run typed reachability from the selected roots after rewriting. This removes records made redundant or unreachable by sharing. Preserve existing treatment of nominal declarations and all reference-bearing authority data.

Reachability is cleanup after validation, not a way to evade malformed unused declarations, invalid exports, or false component contracts. For attribution, compare against the same ordinary reachability projection with coalescing disabled; do not count already-dead records as a code-sharing win.

#### A.8.5 Exact cost selection over valid materializations

Full equivalence discovery and physical extraction answer different questions. The first establishes which distinctions may be removed; the second chooses a representation within that permission. A largest equivalence class does not establish a smallest encoding, a fastest admission analysis, or a smallest checkpoint. Treat those latter claims as separate measured questions.

Use this small mandatory portfolio, implemented through the same records, refinement, relocation, and validator:

| Profile | Meaning |
|---|---|
| `baseline` | Existing local optimizations and typed reachable projection, with no new coalescing. |
| `descriptions` | Existing structural schema equivalence and exact literal/capture sharing, plus eligible constructor/handler description sharing while **every function identity remains singleton**. Refine descriptor dependencies under those singleton function identities. |
| `full` | The complete eligible function/constructor/handler quotient, together with the same structural description sharing. |

Profiles are internal extraction choices in the mandatory canonical pass, not public modes. Comparing a description-only candidate does not satisfy required positive code-sharing witnesses. The previous minimum real-consumer code-sharing gate is retired; actual consumer outcomes remain reported.

For each nontrivial candidate:

1. Construct its complete, stable correspondence witness and actual rewritten records.
2. Run production transformation validation against the current live program.
3. Project newly unreachable records through the existing typed mechanism, compose the correspondence, and validate the final projected correspondence. The final check may subsume intermediate checks when it covers all the same obligations.
4. Independently admit the candidate. A failing candidate is an explicit defect/error, even when a different candidate is valid. Do not hide it behind cost selection.
5. Determine its exact canonical BPI3 encoded length with the existing codec or an exactly equivalent counting sink.

A candidate is eligible for selection only if its encoded length is no greater than the current baseline's, it contains a genuine live merge, and its total live catalogue-entry count is strictly smaller. The count includes every catalogue kind in existing `relocation.sizes`, including declared regions, and uses checked arithmetic. Instruction counts remain reported separately.

Among eligible candidates, choose lexicographically by:

```text
(exact BPI3 byte length, total live catalogue-entry count, fixed profile order)
```

Use `full` before `descriptions` only to resolve a remaining exact tie. If neither candidate qualifies, retain the current baseline's exact bytes. This selects the cheapest of the specified valid candidates, not a globally optimal program and not necessarily the fastest one to execute.

A changed reference sequence can affect compact ID-vector encoding; counts alone are not a byte-size proof. Count with the actual grammar, including the frame and integer/vector encoding decisions. Test every counting path against actual encoding. A codec-cost estimate or additive per-class savings estimate cannot authorize publication.

If full code sharing is rejected by size selection but description sharing is selected, report both facts. Do not discard an independently useful candidate solely because another valid candidate is larger. Conversely, retain the required actual code-sharing positive witnesses; a description-only implementation does not complete P01, even though the real-Agent minimum-benefit gate is retired.

Release rejected candidates and their scratch. Returned construction ownership contains only selected records and their freshly derived admission facts. No candidate portfolio, witness, source AST, or benchmark-specific whitelist enters the wire image or runtime.

#### A.8.6 Fixed-point, termination, and no-change properties

Discover the full eligible relation to completion at each extraction round. A profile may retain more classes, but it must be a stable relation under its stated restrictions. A one-pass leaf matcher or an unfinished recursive partition is not complete discovery.

Apply the portfolio to the current selected program until no eligible candidate improves it. Each accepted round must reduce the finite live catalogue-entry count strictly and may not increase BPI3 length. No record-splitting, new wrappers, or instruction expansion is allowed. Thus the original finite catalogue count bounds the number of successful rounds; the independent work budget still protects pathological cost.

An implementation may prove that its portfolio is absorbing and avoid redundant rounds, but it must satisfy the same fixed-point result. It may not assume absorption merely because a single maximal quotient is idempotent: a cost-selected restricted quotient is a different operation.

For the same admitted input and options:

```text
encode(safe(P)) == encode(safe(P))          # deterministic
encode(safe(safe(P))) == encode(safe(P))    # idempotent
```

Here `safe` is the closed-record optimization/projection path, not another invocation of source emitters. If the deterministic work limit is hit, return the original baseline rather than a partial multi-round result. On a true no-op, keep the ordinary baseline bytes; comparison normalization must not churn physical layouts or image identity.

Compose per-round correspondence maps to retain original-to-final provenance. Intermediate maps cannot be used as final diagnostic IDs. Every accepted transformation is checked; the final emitted record owner and its admission facts must be exactly those of the selected result.

Statistics distinguish full-discovery opportunities, profile restrictions, size rejection, actual merges, and extraction rounds. Only selected live changes count as delivered reductions. Within-profile completeness is not a requirement to materialize every possible full-discovery merge when the specified cost rule chooses another profile.

### A.9. Compiler and linker integration

#### A.9.1 Direct compilation

Preserve the current architecture and entrypoints. The required sequence is:

```text
source checks, including original declarations
    -> ordinary lowering
    -> original target admission
    -> existing local optimizations
    -> existing typed live projection and required baseline checks
    -> equivalence discovery and candidate construction
    -> production correspondence validation and candidate admission
    -> exact cost selection to a fixed point
    -> final admission facts for the exact selected records
    -> returned owned construction
    -> ordinary BPI3 encoding
```

Keep the original target check before this new pass. Existing trusted local transformations can feed the pass as they do today; the specification does not require gratuitously duplicating every existing admission stage. The original and selected-output checks must remain independent, and no previously checked contract may be dropped. Reuse the existing baseline projection/check and the selected candidate's final admission facts where they are already exact; the specification does not require checking the identical immutable candidate twice merely to match separate bullet points.

The shared optimizer must not need source ASTs, lexical variable names, compiler caches, or source-emitter callbacks. Source-specific diagnostics are a caller responsibility using returned/scratch provenance.

At the freshly inspected typed-authoring head, preserve `Options.captures` and its original `capture`/`closure` callbacks. Closure observations currently happen for original source values before constructor-cache reuse; effect-boundary observations use source slot-to-variable correspondence. Collect those original-source observations before global coalescing and retain their original source identity. The current `authoring.Context.lowerNamed` checks `capture_failure` after `source.lowerObserved` returns and deinitializes the provisional result on failure; preserve that publication gate rather than moving source-specific checks into the data-only optimizer. No caller-visible compiled result is accepted until the original named-capture checks succeed. A shared representative is not permission to skip an original occurrence's capture evidence. [S24] Do not expose new representative IDs through an interface expecting source IDs. Preserve diagnostic clearing before a subsequent admission attempt, including allocation failure without a location. [S18] [S19]

The historical `authoring.Context.compile`/`lowerNamed` boundary must preserve mandatory named-capture observation and publication. Reuse current options-taking entrypoints for observations and deterministic resource controls, not `off`/`safe` selection. Every closed authoring compile reaches the same canonical pass. Optional observers cannot replace required capture evidence or bypass `capture_failure`. Test the canonical typed path directly; maintain attribution through independent references, not a restored production bypass. [S24]

#### A.9.2 Component compilation

BMO1 compilation is not a closed world. The new global coalescing pass MUST NOT erase exported identities or make unbound assumptions while emitting a component.

For this version, defer the new pass until final link. Keep the existing component checks, interfaces, import assumptions, export guarantees, borrow summaries, and ordinary emission semantics. Open-component emission must defer P01; observations may report `deferred_open_component`. Compare the same original BMO1 obligations and component inputs without adding a production mode merely to recreate the historical experiment.

This does not prohibit existing local component optimizations. It prevents this work from turning component emission into an unsound whole-program boundary.

#### A.9.3 Closed linking

The required link order is:

```text
decode and admit every original BMO1 object
    -> establish instance ordering and resolve explicit bindings
    -> typed relocation and existing schema reconciliation
    -> check every imported/exported interface and borrow obligation
    -> full closed admission of the linked baseline
    -> existing typed reachable baseline and required checks
    -> shared discovery, candidate construction, and production validation
    -> exact cost selection to a fixed point
    -> final reachable records and admission facts for selected output
    -> ordinary BPI3
```

Avoid repeating projection if it is already part of the shared selection path. The ordering requirement is validation before removal, not a demand for redundant copies.

All current `checkBorrows` obligations, including otherwise unreachable declarations and constructor/handler substitution checks, MUST run against the original resolved linked program before coalescing. Coalescing must not make a false declaration appear valid by replacing it with a different valid implementation.

After transformation, derive full closed borrow/ownership facts again. If original summaries remain in use after transformation, relocate all their selectors and check them individually; do not combine multiple guarantees into a permissive union. If they have been fully discharged and are no longer used, do not retain them unnecessarily in the returned BPI3 construction.

The linker remains data-only. Tests must prove it can complete this pass using only separately produced objects, a manifest, and the data-only linking executable. Source emitters, application source, Agent authoring modules, and World must not be required during linking.

#### A.9.4 Agent propagation

`agent.compileObserved` already carries Boundary options. That selection MUST reach both direct lowering and the final link in `compiled_tool.zig` rather than stopping at the intermediate wrapper component.

The same Agent application must reach mandatory coalescing through its existing direct and final-link paths. Compare against independent historical/test controls, not an installed disable option. Do not add a separate Agent optimizer or change source generation merely to manufacture measured gains.

Maintain Agent admission before Boundary compilation. Include applications using compiled tools, protected authoring, ordinary algebraic effects, and hyperfunction-based interaction in consumer evidence.

### A.10. Configuration, observations, and ownership

#### A.10.1 Mandatory invocation and minimal observation/resource options

There is one coalescing implementation, invoked by all production closed-compilation and final-link entrypoints. Keep removed the public `Mode` type, `Options.mode`, and CLI/manifest/fixture production selectors. Reject retired `off` and `safe` inputs rather than interpret them as an alternate product path.

Retain caller-owned optional statistics, diagnostics, and genuine deterministic resource budgets. Existing default and options-taking entrypoints can share one implementation; they are not alternatives when both invoke P01. Normal defaults must complete required fixtures, not use a tiny budget as a disguised bypass.

Preserve baseline/descriptions/full candidate selection, exact cost guards, eligibility, idempotence, and explicit original-baseline rollback on work exhaustion. Distinguish running P01 with no legal beneficial merge from failing to invoke it. Independent comparison lives in frozen inputs/checkouts or a narrow uninstalled test reference, not the shipped compiler.

No new wire flags, authenticated request fields, schema tags, or runtime modes are permitted. Codecs remain identity-preserving operations on supplied data and do not implicitly coalesce. Open components defer the pass until closed linking.

#### A.10.2 Observability

Extend existing phase observation with one attributable coalescing phase rather than creating a general event bus. An observer must not change output bytes. No mandatory filesystem writes or logging occur inside the library.

Optional statistics MUST distinguish:

| Category | Required observation |
|---|---|
| Outcome | `disabled`, `deferred_open_component`, `no_change`, `applied`, `size_guard`, or `work_limit`; errors remain errors. |
| Baseline | Reachable counts for schemas, literals, functions, blocks, instructions, handlers, captures, constructors, effects, regions, resources; baseline BPI3 length. |
| Candidate | The same counts and exact candidate length, even when the size guard rejects it if a valid candidate was produced. |
| Selected result | Final counts and bytes; merges actually selected, not merely attempted. |
| Analysis | Candidate groups, exact comparisons, refinement work/rounds, profile restrictions, and meaningful exclusion counts. |
| Selection | Full-discovery class counts, evaluated profiles, exact per-profile sizes, selected profile per extraction round, total extraction rounds, and composed original-to-final merge counts. |
| Validation | Transformation-validator work, candidate admission work, and explicit failed witness/check status. No error is a successful outcome. |
| Resources | Pass time and peak scratch/allocation evidence through the existing measurement facilities. |

Function/body merges, descriptor merges, and ordinary reachability removal must be attributable separately. Statistics need not encode every internal implementation detail or become a permanent telemetry schema.

Optional observations MUST NOT retain source ASTs, compiler arenas, program bodies, or large provenance tables after compilation. Production transformation validation is mandatory even when statistics and phase observers are disabled. Native source-capture observation retains its separate, original-source contract and is not replaced by these statistics. A caller that does not request statistics should not pay for report formatting or retained diagnostics.

#### A.10.3 Allocation and ownership

The pass borrows its input only during the call. Scratch maps, fingerprints, comparison views, worklists, and original-to-representative correspondence must not escape into long-lived program records.

Returned construction ownership and `deinit` behavior remain consistent with existing Boundary APIs. Every selected record slice must remain valid after the input builder/component buffers and analysis scratch are released.

Repeated calls and concurrent independent compilations must not share mutable optimizer state. Do not store persistent caches keyed by pointer address or assume an arena address identifies an emitter configuration.

### A.11. Provenance, diagnostics, and trust

#### A.11.1 Many origins, one representative

A merged function can represent several original functions with different lexical variable IDs. Capture-description merging also means a single capture record can be used by several constructors/functions.

Update diagnostic translation so it does not select an arbitrary first constructor with a matching capture and attribute an error to that constructor's lexical variable. The inspected lowering still scans constructors this way; it is not a sufficient many-origin model. Its newer source-capture observers add an independent original-occurrence contract that also must survive, including the outer named-capture publication gate. [S1] [S18] [S19] [S24]

The implementation MUST:

- Preserve a representative origin and enough alias/local correspondence while checks run.
- Prefer the actual failing instruction/constructor/function occurrence when available.
- Report the representative and related origins when a unique original cannot be determined.
- Never fabricate one source variable as the unique cause of an ambiguous merged record.

Do not build a permanent source-map service. Caller-owned or temporary maps are sufficient. No diagnostic/provenance records enter BPI3, BMO1, PST3, or identity hashing.

#### A.11.2 Mandatory production transformation validation

Implement one small, data-only acceptance checker for the proposed quotient. It runs in production builds for every nontrivial candidate and is used by tests as well. Failures use explicit error returns; the checks must not disappear with debug assertions or build optimization settings. This is translation validation: check a particular optimizer result rather than assuming discovery or rewriting is correct. Verified register-allocation validation provides a precedent for this separation; this specification does not claim that Boundary's new checker is already formally verified. [S21]

The temporary witness supplies global representative/final maps, selected profile restrictions, local function correspondences, and provenance needed for checking. It has no portable serialization, no new public certificate grammar, and no runtime retention. Validating a witness must never execute a program or call a source emitter.

The checker receives the original admitted live records, the **actual candidate records**, and the witness. It must establish:

| Obligation | Required check |
|---|---|
| Domains and kinds | Every required live original reference has a valid image of the correct kind; every retained candidate record has justified provenance. No missing sentinel masks a live reference. |
| Representatives | Maps identify consistent classes and actual representatives; no cyclic or out-of-range representative chain. Local functions map as complete bodies. |
| Nominal identity | Retained effects, regions, and resources map injectively; original pinned identities are neither merged away nor made targets of another identity's merge. |
| Scalar and ordered fields | All semantic fields, lengths, bounds, modes, usage contracts, opcodes, immediates, constants, failure tables, and ordered list positions match under approved maps. |
| Local correspondence | Block, slot, and custody maps are total required bijections with correct schemas, entry/interface order, repeated-slot relationships, and custody ancestry. They preserve simultaneous assignments and full bodies. |
| Reference commutation | Every role-labeled reference and occurrence agrees between original and representative, and between representative and the actually emitted record, including back edges and recursive groups. |
| Runtime-instance preservation | The rewrite does not remove or combine construction/installation operations, alter ordered capture operands, or introduce a state-node map. The semantic argument covers operations' dynamic behavior. |
| Roots and reachability | Roots correspond; cleanup removes only records absent from the established typed live closure after the checked rewrite. Source/link obligations were already discharged before projection. |
| Output identity | The exact checked immutable records are those sized, admitted, and published; no unchecked mutation occurs after validation. |

Read raw record fields and the proposed correspondence directly. The checker MUST NOT merely call the discovery comparator, compare stored fingerprints, replay candidate bucket membership, or trust discovery-normalized views as its source of truth. Sharing exhaustive record definitions and primitive field-access helpers is acceptable; sharing the conclusion being checked is not.

Test corruption of **both** witnesses and candidate records. Important example: changing a well-typed return constant from `41` to `42` may leave both programs individually admissible, but the correspondence checker must reject the transformation. This test distinguishes semantics preservation from validity.

A failed check is an explicit optimizer error, not `no_change`, `size_guard`, a clean review, or permission to choose a different candidate and conceal the defect. A completed valid candidate later rejected solely for cost is a normal outcome. Keep those cases distinct.

The validator is part of the trusted implementation and requires direct tests and a correctness argument. Its presence reduces reliance on a sophisticated search implementation; it does not remove bugs by definition or establish a theorem about the entire compiler. Tests must include mutation cases capable of finding a jointly wrong discovery/rewriter pair.

#### A.11.3 Invalid inputs must remain invalid

Do not use optimization to sanitize an invalid source module, BMO1 object, linked interface, capture, ownership relationship, or borrow summary. Retain rejection of malformed unused declarations and unreachable false contracts where the current API checks them.

Tests must show both `off` and `safe` reject the same invalid fixture for the same semantic reason. Exact diagnostic IDs may differ only where the API already permits relocation; the compiler must not report completion on a failed check.

### A.12. Wire compatibility and program identity

The optimizer emits ordinary BPI3 using the existing grammar. Decoders and admission MUST continue to accept otherwise valid unoptimized programs containing duplicate structural/code records. Optimization is not a new canonical-wire admissibility condition.

Encoding/decoding a supplied program must not silently run this pass. Otherwise byte identity, hashes, diagnostics, and saved-state compatibility could change during a nominal codec operation. Perform coalescing only through the explicit compilation/linking path.

A selected optimized program normally has a new program identity because its canonical bytes differ. Catalogue IDs and hash-bound request/checkpoint identities belong to that new program. [S4]

Existing saved executions MUST continue to use their original exact image/runtime pairing. Do not offer automatic old-to-new PST3 migration, treat equal results as identical program identity, rewrite a checkpoint header, or reuse an old authenticated reply against the optimized program. The test harness must construct valid replies independently for each run's actual request.

BMO1/PST3/ABI versions remain unchanged. Changes to ordinary compiler output require corresponding identity/golden updates only where bytes genuinely changed. Existing independent wire-format goldens MUST NOT be regenerated wholesale from the implementation under test. Preserve old valid duplicate-containing BPI3 fixtures as codec/admission compatibility witnesses.

The same selected, authenticated World runtime artifact MUST execute enabled and disabled images within each differential/performance experiment. If dependency maintenance requires rebuilding an artifact, authenticate it and use it for both arms. Do not attribute a runtime/toolchain change to this optimizer.

### A.13. Mandatory behavioral witnesses

The following examples define required capabilities, not merely illustrative possibilities. Implement them with public staged authoring APIs where possible, and use raw admitted-record construction only where an authoring helper already eliminates the distinction under test.

#### A.13.1 Repeated closures with different captured values

Independently emit `N` equivalent functions and their constructors, not `N` references to one function and not a specialization-cache hit. Each implements the same ordered operation over an argument and a captured value.

```text
Closure_0 captures 3:   apply(x) = x + captured
Closure_1 captures 7:   apply(x) = x + captured
...
Closure_N captures k:   apply(x) = x + captured
```

Choose the existing, explicitly specified arithmetic opcode and test both its normal and failure/overflow behavior as applicable.

For the equivalent family, the selected output must have one representative body, one compatible constructor, and one capture description rather than one of each per independent declaration. The constructions and captured values remain distinct. Applying the first two to `10` must still produce `13` and `17`.

Use `N = 1, 2, 16, 64, 256` for scaling. The shared family has constant body/constructor cardinality. The entire application need not have constant size: distinct constants, construction sites, and outputs can legitimately grow with `N`.

#### A.13.2 Same payload shape, different behavior

Independently emit add/subtract closures with the same capture shape and callable schema. They MUST remain different code/constructor classes. Equivalent capture descriptions may still share. Also test a one-opcode difference, one-immediate difference, one failure payload difference, and a swapped branch/variant result.

#### A.13.3 Reference-induced sharing

Construct two separately emitted, equivalent helper trees whose parents initially refer to different child function/constructor IDs. Require parent sharing after child equivalence is established. Include depth at least eight and both direct calls and constructed computations.

A leaf-only pass, equality by original global IDs, or a fixed single scan does not satisfy this witness.

#### A.13.4 Recursive groups

Construct two independently emitted equivalent mutually recursive groups, with distinguishable roles such as even/odd or request/response participants. They must coalesce role-for-role while preserving their control behavior. Include a function-local loop with renamed block and slot IDs.

Change a deep base-case value, nominal effect, or handler mode in a near-duplicate group. Refinement must propagate the difference so an affected parent/recursive participant is not incorrectly merged.

Test both terminating executions and matched finite prefixes/work-quantum resumptions of a nonterminating program. Do not treat a timeout as proof of equivalent divergence.

#### A.13.5 Repeated hyperfunction authoring

Exercise ordinary `hyper` helper paths that independently emit equivalent thunks, in addition to a deliberate staged fixture. Preserve lazy demand behavior, recursive interfaces, reciprocal calls, and captured values.

Include two calls to an authoring helper with genuinely different Step/configuration behavior. They MUST retain their difference. Do not obtain sharing by caching emitters before their configuration-specific code has been emitted.

Include call-by-need cases proving that separate dynamic memo cells remain separate and that a deliberately shared cell remains shared. Coalescing code is not memoization.

#### A.13.6 Separately compiled components

Compile at least two objects in independent emitter processes that contain equivalent private helper code. Link both objects into one closed application from object bytes alone. Require an actual cross-object code/constructor merge when their resolved contracts permit it.

Repeat with distinct private nominal effects/regions/resources having equal names and shapes. Those anchors must remain distinct, and code whose behavior depends on different anchors must not merge across them. Repeat with explicit imports that legitimately unify an effect before linking; sharing may then become possible.

Include mutually recursive linked functions, exported/imported constructors or handlers where supported, and original borrow obligations. Successful linking must not require application source, a shared builder, or an emitter specialization cache.

#### A.14.1 Differential and generative testing

Add a bounded generator for small well-formed programs in the supported structural subset. Generate duplicate code under fresh IDs, local renamings, recursive references, and one-field semantic mutations. Retain seeds and minimized counterexamples as ordinary regression fixtures.

For each generated valid program, compare enabled and disabled execution and validate the quotient correspondence through the production checker. Separately mutate maps and emitted records so the checker is tested independently of successful discovery. For invalid mutations, compare rejection. Sampling is evidence, not a claim of a formal proof over all programs.

The generator/reference evaluator MUST NOT reuse the optimizer's equality judgment to decide what the expected result should be. Reuse existing independent higher-order/source oracles where applicable. Hand-authored expected traces remain necessary for authority, cleanup, and suspension cases.

#### A.14.2 Runtime comparison procedure

For each required execution fixture:

1. Compile or link one disabled image and one enabled image from identical authored/object inputs.
2. Execute both with the same runtime artifact and a deterministic environmental responder.
3. Compare semantic request fields and canonical payload bytes through the injective nominal map. Normalize only derived program/request IDs explicitly permitted by Section 4.
4. Supply each execution with a reply valid for its own actual request/envelope.
5. Compare results, faults, cleanup traces, yields, retained branches and state aliasing at matched boundaries.
6. Save state at relevant boundaries; transfer and resume each state with its own image on a fresh runtime/host. Compare the continuation behavior, not raw PST3 bytes between distinct programs.

Do not drop “inconvenient” trace fields, compare only final values, or regenerate expected traces from the optimized run. A divergence report must include the first differing semantic boundary and a reproducible input.

#### A.14.3 Platform coverage

Run the existing Boundary authoring/data/component/semantic checks and the relevant Agent aggregates. Validate new positive and semantic-risk fixtures in native World and Node/WASM. Use the existing independent Wasmtime and browser/source-free transfer witnesses where available in the repository's qualified suite; do not retire them to simplify this task.

Actual missing tools/platforms must be reported as `UNAVAILABLE`, not passing. Keep portable compilation checks distinct from host-specific execution qualification. An unavailable required qualification is an outstanding delivery item, not an excuse to infer success from a neighboring platform.

### A.15. Baselines and measurement protocol

#### A.15.0 Opportunity census before profitability claims

Produce a repeatable census over the existing, unchanged Agent and Boundary workload images. This may be an internal measurement mode using the same discovery implementation; it must not become a second public compiler workflow or a persistent service.

Record live function/body/constructor/capture/handler counts, equivalence-class membership, and reasons for important non-merges: different instructions or literals, distinct nominal anchors, capture ABI differences, pinned identities, or justified analysis-precision exclusions. Identify real authoring sites through temporary provenance. Report both direct and component-linked paths.

A failed search for duplicates establishes only that this relation found none in that input. It does not prove no stronger safe optimization exists. Conversely, approximate fingerprint similarity is not a proved opportunity, and per-class byte-savings estimates are not additive when global IDs and wire compression interact.

This census decides where implementation effort has concrete leverage; it does not replace the mandatory synthetic, recursive, source-free, and semantic-risk witnesses or permit changing a real workload to manufacture success.

#### A.15.1 Three baselines, not one

Record:

| Arm | Purpose |
|---|---|
| B0: current pinned predecessor | Detect integration/instrumentation/default-path regression relative to the actual starting point. |
| B1: implementation revision, coalescing `off` | Isolate the new pass from unrelated code and dependency changes. |
| B2: same implementation revision, coalescing `safe` | Measure the selected optimization against B1 with all other inputs fixed. |

The primary attribution is B2 versus B1. B1 versus B0 verifies that the control did not regress or silently change. A separately reported direct-versus-linked comparison is useful, but those paths need not have byte-identical images because existing catalogue ordering and schema reconciliation can differ.

#### A.15.2 Required workload families

Measure the following without changing the authored workload between arms:

- The independently emitted closure scaling family, reference-induced helper trees, and recursive-group fixtures.
- A low-duplication/no-duplication control and a large mostly unique graph to reveal overhead and pathological comparisons.
- Repeated hyperfunction authoring, a retained/suspending interaction, and an ordinary effect-handler composition.
- The source-free multi-component witness, including a case where explicit binding exposes sharing.
- The actual Agent document, review/ReAct, inquiry/repeated, clarification, and compiled-tool/transfer workloads available in the selected revision. Record exact names and which aggregates cover them rather than assuming a historical list is current.

Agent measurements MUST include at least one direct compilation and one final component-linking path. Synthetic duplicate-heavy workloads alone cannot establish a real Agent improvement.

#### A.15.3 Metrics

Report before/candidate/selected counts and bytes, then separate these costs:

| Phase/artifact | Required measurements |
|---|---|
| Source construction | Emitter time separately from Boundary lowering; not included in a misleading optimizer-only denominator. |
| Compilation | Total elapsed time; discovery, materialization, transformation-validation, candidate-admission and exact-cost time; allocations/allocated bytes and peak memory. |
| Linking | Decode/validation, linking, coalescing and total cost; source-free inputs only. |
| Program data | Exact BPI3 byte length and per-catalogue counts; attribution by merged body, descriptor, and newly unreachable record. |
| Admission | Cold program admission/setup time and peak memory, separately from file loading when possible. |
| Execution | Fresh-invocation and resident execution time in native and WASM; logical work counters and allocator/peak evidence. |
| State | Checkpoint bytes, save/restore cost, and peak runtime memory; identity differences disclosed. |
| Control | B0/B1 equivalence, selected runtime/kernel identity, toolchain, platform, options, and qualification status. |

Do not infer a checkpoint improvement from a smaller program image, or a runtime-kernel improvement from fewer program constructors. Do not report unchanged numbers as improvements.

#### A.15.4 Reproducibility and noise

Use the same machine, optimization level, runtime artifact, input/reply sequence, capacities, and toolchain for each B1/B2 pair. Separate cold and warm measurements. Avoid comparing fresh invocation on one arm with resident execution on the other.

For timed cells, collect at least three independently launched alternating B1/B2 windows. Each measured process uses at least three warmups and nine samples unless an existing stronger qualified harness already specifies a protocol. Publish the protocol and paired per-window medians, plus enough raw observations to reproduce the summary. Do not use a single best run.

A suspected regression requires two additional alternating confirmation windows before it is dismissed as noise or reported as reproducible. Report variance/inconclusiveness; do not hide it behind an aggregate average. Confidence intervals may supplement the windows but are not a substitute for matched inputs.

Keep maintained harnesses and summarized machine-readable measurements in the repositories. Large generated binaries, temporary profiles, and irrelevant build products do not need to be committed. Record commands and toolchain identities so the evidence is reproducible.

### A.16. Promotion and success criteria

The following are prospective engineering acceptance thresholds for this work, not measurements already observed.

#### A.16.1 Mandatory structural gates

- All semantic, safety, ownership, determinism, component, and codec tests in Section 14 pass on their required qualified paths.
- Duplicate-family and source-free component fixtures demonstrate actual function-body and constructor sharing, not merely literal/schema interning or preexisting dead-record removal.
- The equivalent family from 13.1 has constant representative body/constructor cardinality across `N`, and duplicate-heavy images at `N >= 16` are strictly smaller than their disabled baselines.
- Parent and recursive sharing witnesses pass; unsupported-cycle skips do not satisfy the requirement.
- Every selected nontrivial rewrite passes the production validator. Corrupted witnesses and separately admissible-but-wrong outputs are rejected independently of discovery.
- Both materialization profiles and the fixed-point selector pass their tests; selection reasons and any unrealized full-discovery merges are reported explicitly.
- Every selected enabled image in the maintained corpus is no larger than its disabled BPI3 baseline. The exact size guard is exercised and verified independently.
- The work-limit default does not skip required fixtures or the real consumer corpus. Any other workload that hits it is identified explicitly.

A schema/capture-only implementation does not complete the task, even if it makes one image smaller.

#### A.16.2 Real-consumer evidence; former minimum-benefit gate retired

Keep the unchanged Agent census and report actual code/constructor/description outcomes honestly. No current-real-Agent reduction or runtime speedup is required to retain the already accepted P01 foundation. This incorporates the accepted coalescing v2.1 disposition and the current mandatory-adoption instruction.

Do not inflate workloads to demonstrate a win. Synthetic closure, recursive, hyperfunction, and source-free cross-object witnesses must still demonstrate real code sharing. A description-only implementation does not satisfy those witnesses. Missing opportunities in real inputs are not evidence that generalized computation, P02–P31, or P01 should be removed.

#### A.16.3 Runtime/admission non-regression gates

For each required real workload and qualified runtime:

- A reproducible median slowdown greater than **5%** in fresh invocation, resident execution, or program admission is a promotion blocker. Treat it as reproducible when the median paired ratio over the three original plus two confirmation windows exceeds `1.05` and at least four of the five window ratios exceed `1.05`.
- Measured peak live memory must not increase beyond `max(1 KiB, 1% of the baseline peak)` in the same harness/profile. A larger reproducible increase is a promotion blocker, even when the BPI3 image shrinks.
- No required checkpoint grows beyond `max(64 bytes, 1% of its baseline checkpoint size)` without a documented causal explanation and an explicit, separately approved tradeoff. An unapproved excess blocks promotion; it is not silently accepted as the price of code sharing.
- Existing exact semantic work-count requirements, capacity safety, and caller-visible error contracts remain hard gates regardless of percentage thresholds.

These thresholds prevent measurement noise from becoming a claim of harm while forbidding material regressions hidden behind image-size gains. Smaller within-threshold regressions must still be reported honestly.

The implementer may remove an unhelpful candidate class/rule using a general, semantics-preserving profitability restriction and rerun all evidence. Per-benchmark exclusions, changed workloads, tuned environmental replies, and relaxed runtime checks are prohibited.

#### A.16.4 Compilation and linking cost

There is no predetermined percentage cap on additional compilation/linking time: the user explicitly accepts extra work for better output. Nevertheless, report absolute and relative overhead, peak scratch, and scaling for duplicate-heavy and mostly unique inputs. A pass that stalls, overflows, leaks, or exhibits avoidable pathological full rescanning is not acceptable merely because compilation can be slower.

Show that disabled overhead relative to B0 is absent or explainable, and that duplicate-heavy growth is attributable to finite work rather than repeated expansion of code/types. Optimize the pass itself when the measured cost does not justify the output benefit. Do not substitute an unsupported theoretical complexity claim for the measurements.

#### A.16.5 Canonical adoption and unresolved checks

P01 is mandatory, not a pending optional promotion. Preserve its correctness/independent-validation obligations and qualify final integrated inputs. Correctness failures remain explicit failures; no size guard or work-limit branch may conceal them.

Keep comparison-only predecessor artifacts outside the installed production graph. A documented size rejection/no-op or deterministic original-baseline rollback on work exhaustion remains valid bounded optimizer behavior, with accurate observations and no claim that skipped work completed.

Compiler-only overhead already accepted by the user does not reopen delivery. New World-side costs receive the stricter measurement/disposition policy in Part I and Section 9. Record exact remaining checks or decisions; do not claim a pass or keep a legacy compiler to evade them.

### A.17. Implementation sequence

Execute these milestones in order of dependency. They are work packages inside this single specification, not additional approval gates.

#### M1 — Establish the baseline and identity audit

Refresh source/locks, record B0 and its current checks, inspect all identity-sensitive references, and preserve a disabled control. Run the live-image opportunity census without altering applications. Record exactly which functions/descriptors must be pinned.

**Exit evidence:** source tuple, identity policy, existing tests, baseline structural counts, and a real independently emitted duplicate fixture.

#### M2 — Factor reusable structural infrastructure

Reuse schema partitioning and typed relocation. Implement the production raw-record transformation validator and its negative tests before enabling general merging. Establish a narrow executable end-to-end slice with two separately emitted equivalent closures and a separately admissible wrong-output mutant. Then add exact constant/capture equality, comparison views, local correspondences, exhaustive field handling, and deterministic discovery keying. The early slice is evidence of the acceptance path, not completion of the recursive/global requirements.

**Exit evidence:** structural/renaming tests, pinned-identity tests, sum-ordinal tests, collision tests, and source-independent data-module builds.

#### M3 — Coalesce whole code families

Implement finite recursive refinement for function/constructor/handler relationships, deterministic representatives, whole-function rewriting, and post-rewrite reachability. Integrate the description-only and full-code profiles, production correspondence validation, exact cost selection, fixed-point extraction, idempotence, and allocation/work-limit failure checks.

**Exit evidence:** leaf, parent, recursive and cross-descriptor sharing; no live-state changes; all selected images valid and no larger than their disabled baselines.

#### M4 — Integrate both Boundary paths and Agent

Integrate ordinary compile and final link without changing open-component emission. Preserve original contract checks and current typed-authoring capture observations, fix many-origin diagnostics, propagate options through Agent's compiled-tool path, and update authenticated dependency bindings as needed.

**Exit evidence:** direct and source-free linked executions, unchanged component bytes across global modes, accurate diagnostics, current consumer builds and authenticated tuple.

#### M5 — Qualify semantics and measure economics

Run all mandatory tests and platform qualifications. Produce B0/B1/B2 evidence for the required synthetic and real workloads. Investigate every regression and retain minimized counterexamples. Use the same runtime artifact for each enabled/disabled comparison.

**Exit evidence:** completed test matrix, exact sizes and structural deltas, compiler/linker costs, runtime/admission/state results, and a gate-by-gate promotion decision.

#### M6 — Finish the delivery

Enable the default only when qualified, remove experimental variants and redundant code, update docs/examples, and publish the authorized draft changes with linked evidence. Verify the final commits, not an earlier intermediate tree.

**Exit evidence:** reproducible final commands, authenticated inputs, linked draft PRs where changes are necessary, and an explicit final result against this specification.

### A.21. Executable finite reference model and observed evidence

```python
"""Finite structural-quotient model, not a Boundary compiler/runtime model.
Run with Python 3.10+; no third-party dependencies. Assertions are test checks.
"""
from dataclasses import dataclass, replace
from itertools import product
import json
import random


@dataclass(frozen=True)
class Node:
    kind: str
    label: tuple
    edges: tuple[tuple[str, int], ...] = ()
    anchors: tuple = ()
    pinned: bool = False


def local_key(node: Node, index: int) -> tuple:
    return (node.kind, node.label, node.anchors,
            index if node.pinned else None,
            tuple(role for role, _ in node.edges))


def group(keys: list[tuple]) -> tuple[int, ...]:
    first: dict[tuple, int] = {}
    return tuple(first.setdefault(key, i) for i, key in enumerate(keys))


def refine(nodes: tuple[Node, ...], seed=None) -> tuple[int, ...]:
    """Split-only discovery; representatives are first original members."""
    for node in nodes:
        if any(not 0 <= target < len(nodes) for _, target in node.edges):
            raise ValueError("invalid reference")
    classes = group([(local_key(n, i), None if seed is None else seed[i])
                     for i, n in enumerate(nodes)])
    while True:
        refined = group([(classes[i], local_key(n, i),
                          tuple((role, classes[t]) for role, t in n.edges))
                         for i, n in enumerate(nodes)])
        if refined == classes:
            return classes
        classes = refined


def pair_oracle(nodes: tuple[Node, ...]) -> set[tuple[int, int]]:
    """Independent greatest-relation deletion, not partition refinement."""
    pairs = set()
    for i, a in enumerate(nodes):
        for j, b in enumerate(nodes):
            if (a.kind == b.kind and a.label == b.label and
                a.anchors == b.anchors and
                (not (a.pinned or b.pinned) or i == j) and
                len(a.edges) == len(b.edges) and
                all(x[0] == y[0] for x, y in zip(a.edges, b.edges))):
                pairs.add((i, j))
    while True:
        bad = {(i, j) for i, j in pairs
               if any((a[1], b[1]) not in pairs
                      for a, b in zip(nodes[i].edges, nodes[j].edges))}
        if not bad:
            return pairs
        pairs.difference_update(bad)


def validate_map(nodes: tuple[Node, ...], q: tuple[int, ...]) -> bool:
    """Direct field/edge checks; never asks discovery whether nodes match."""
    if len(q) != len(nodes):
        return False
    if any(type(r) is not int or not 0 <= r < len(nodes) for r in q):
        return False
    if any(q[r] != r for r in q):
        return False
    for i, a in enumerate(nodes):
        b = nodes[q[i]]
        if (a.pinned or b.pinned) and i != q[i]:
            return False
        if a.kind != b.kind or a.label != b.label or a.anchors != b.anchors:
            return False
        if len(a.edges) != len(b.edges):
            return False
        for (role_a, target_a), (role_b, target_b) in zip(a.edges, b.edges):
            if role_a != role_b or q[target_a] != q[target_b]:
                return False
    return True


def quotient(nodes: tuple[Node, ...], q: tuple[int, ...]) -> tuple[Node, ...]:
    if not validate_map(nodes, q):
        raise ValueError("invalid quotient witness")
    reps = sorted(set(q))
    dense = {old: new for new, old in enumerate(reps)}
    return tuple(replace(nodes[r], edges=tuple((role, dense[q[t]])
                       for role, t in nodes[r].edges)) for r in reps)


def check(nodes: tuple[Node, ...]) -> None:
    q = refine(nodes)
    expected = pair_oracle(nodes)
    actual = {(i, j) for i in range(len(nodes)) for j in range(len(nodes))
              if q[i] == q[j]}
    assert actual == expected
    assert validate_map(nodes, q)
    reduced = quotient(nodes, q)
    assert refine(reduced) == tuple(range(len(reduced)))


def main() -> None:
    exhaustive = 0
    for size in range(1, 5):
        # All unary directed graphs, every node independently labeled 0 or 1.
        for labels in product(range(2), repeat=size):
            for targets in product(range(size), repeat=size):
                nodes = tuple(Node("code", (labels[i],), (("next", targets[i]),))
                              for i in range(size))
                check(nodes)
                exhaustive += 1

    rng = random.Random(20260925)
    generated = 500
    for _ in range(generated):
        size = rng.randint(1, 12)
        nodes = tuple(Node(
            rng.choice(("function", "constructor", "handler")),
            (rng.randrange(3),),
            tuple((str(j), rng.randrange(size)) for j in range(rng.randrange(4))),
            (rng.randrange(3),), rng.randrange(7) == 0)
            for _ in range(size))
        check(nodes)

    # Two equivalent recursive pairs fold role-for-role.
    rec = (Node("f", ("even",), (("call", 1),)),
           Node("f", ("odd",), (("call", 0),)),
           Node("f", ("even",), (("call", 3),)),
           Node("f", ("odd",), (("call", 2),)))
    assert refine(rec) == (0, 1, 0, 1)
    near = rec[:3] + (replace(rec[3], label=("different-base-case",)),)
    assert refine(near) == (0, 1, 2, 3)
    assert not validate_map(near, (0, 1, 0, 1))

    # Parent witnesses depend on child classes; arbitrary subsets need not be congruences.
    graph = (Node("f", ("parent",), (("call", 2),)),
             Node("f", ("parent",), (("call", 3),)),
             Node("f", ("leaf",)), Node("f", ("leaf",)))
    assert refine(graph) == (0, 0, 2, 2)
    assert not validate_map(graph, (0, 0, 2, 3))
    assert refine(graph, seed=(0, 0, 2, 3)) == (0, 1, 2, 3)

    anchors = (Node("f", ("perform",), anchors=("effect-a",)),
               Node("f", ("perform",), anchors=("effect-b",)))
    assert not validate_map(anchors, (0, 0))
    pinned = (Node("f", ("same",), pinned=True), Node("f", ("same",)))
    assert not validate_map(pinned, (0, 0))
    assert not validate_map(pinned, (1, 1))
    assert not validate_map(graph, (1, 0, 2, 3))  # cyclic representative map

    # Same field shape and arity, different meaning: ordinary typing is not enough.
    results = (Node("f", ("return", 41)), Node("f", ("return", 42)))
    assert not validate_map(results, (0, 0))
    print(json.dumps({"status": "PASS", "exhaustive_unary_graphs": exhaustive,
                      "seeded_labeled_graphs": generated,
                      "adversarial_assertions": 11,
                      "scope": "finite structural reference graph only"}, indent=2))


if __name__ == "__main__":
    main()
```

```python
"""Finite optimizer-law checks and counterexamples, NOT Boundary semantics.
Python 3.10+; standard library only. Checks remain active under python -O.
"""
from functools import reduce
from itertools import product
import json
from operator import xor


def require(condition: bool, message: str) -> None:
    if not condition:
        raise AssertionError(message)


def compose(outer: tuple[int, ...], inner: tuple[int, ...]) -> tuple[int, ...]:
    """Action orientation: (outer o inner)(x) = outer(inner(x))."""
    require(len(outer) == len(inner), "incompatible action domains")
    n = len(outer)
    require(all(0 <= v < n for v in outer + inner), "invalid finite action")
    return tuple(outer[inner[x]] for x in range(n))


def matrix_add(a: tuple[int, ...], b: tuple[int, ...]) -> tuple[int, ...]:
    return tuple(int(x or y) for x, y in zip(a, b))


def matrix_mul(a: tuple[int, ...], b: tuple[int, ...]) -> tuple[int, ...]:
    """Two-by-two matrices over the Boolean semiring, row-major order."""
    return tuple(int(any(a[2*i+k] and b[2*k+j] for k in range(2)))
                 for i in range(2) for j in range(2))


def run_xor(program: tuple[int, ...], state: tuple[int, int], quantum: int,
            accelerated: bool) -> tuple[int, int]:
    """Toy same-image interpreter; grouped dispatch still charges every step."""
    require(quantum >= 0, "negative quantum")
    pc, value = state
    require(0 <= pc <= len(program), "invalid program counter")
    remaining = quantum
    while pc < len(program) and remaining:
        width = min(3 if accelerated else 1, remaining, len(program) - pc)
        value ^= reduce(xor, program[pc:pc+width], 0)
        pc += width
        remaining -= width
    return pc, value


class Fault(Exception):
    pass
```

### C.1 Scope, representation, and provenance

This annex is executable Python 3.10+ using only the standard library. It operates on total affine finite Mealy-style machines with explicitly labeled control edges. It is not Boundary IR, an effect interpreter, a production pass, or a benchmark. Checks remain active under `python -O`.

Matrices are tuples of row bitmasks: bit `i` selects coordinate `i`. The main exhaustive/oracle tests use one-bit coordinates. The word examples additionally test independent bitwise word lanes; the general word-width justification is the algebraic argument in Section 13.6. A machine can have several control locations with different state dimensions, multiple labeled outgoing actions, dynamic input bits, and affine state/output offsets. Its full state space at each location is the test domain. Labels and locations are retained, not quotiented away.

The discovery procedure computes the least observer-row spaces closed under predecessor transitions. Candidate construction derives reduced matrices. The acceptance checker inspects the raw matrix identities independently of discovery. A separate oracle enumerates finite concrete states, evaluates expressions with explicit arithmetic rather than the matrix helpers, and refines behavioral classes until stable. The tests compare both directions of induced equivalence and check every enumerated transition. A breadth-first pair search constructs a shortest distinguishing future action sequence for the reset counterexample.

The checker accepts a sound full-state identity representation even when it is not minimal; economics and minimality are not confused with validity. The finite oracle is deliberately simple and may be quadratic in its number of states. It is test tooling, not a proposed production state enumerator.

```python
"""Exact finite GF(2) observational-state synthesis and independent countermodels.
Python 3.10+, standard library. This is NOT a Boundary optimizer or runtime.
Matrix rows are integer bitmasks; bit i denotes coordinate i. No floats/solvers.
Checks remain enabled under python -O. All finite-state tests cover the full
state space at each control location, not an inferred reachable subset.
"""
from collections import deque
from dataclasses import dataclass, replace
from itertools import product
import json
import random


def require(condition, message):
    if not condition:
        raise AssertionError(message)


def xor_rows(selector, rows):
    result = 0
    for i, row in enumerate(rows):
        if (selector >> i) & 1:
            result ^= row
    return result


def multiply(left, right):
    return tuple(xor_rows(row, right) for row in left)


def apply_bits(rows, value):
    return sum(((row & value).bit_count() & 1) << i
               for i, row in enumerate(rows))


def canonical_basis(rows, width):
    """Discovery implementation: deterministic reduced row echelon basis."""
    work = sorted(set(rows))
    pivot_count = 0
    for column in range(width - 1, -1, -1):
        candidate = next((i for i in range(pivot_count, len(work))
                          if (work[i] >> column) & 1), None)
        if candidate is None:
            continue
        work[pivot_count], work[candidate] = work[candidate], work[pivot_count]
        pivot = work[pivot_count]
        for i in range(len(work)):
            if i != pivot_count and ((work[i] >> column) & 1):
                work[i] ^= pivot
        pivot_count += 1
    return tuple(work[:pivot_count])


def coordinates(row, basis):
    """Find coefficients in an arbitrary independent ordered basis."""
    pivots = {}
    for i, original in enumerate(basis):
        value, coefficient = original, 1 << i
        while value:
            bit = value.bit_length() - 1
            if bit not in pivots:
                pivots[bit] = (value, coefficient)
                break
            previous, previous_coefficient = pivots[bit]
            value ^= previous
            coefficient ^= previous_coefficient
        if value == 0:
            raise ValueError('dependent basis')
    value, coefficient = row, 0
    while value:
        bit = value.bit_length() - 1
        if bit not in pivots:
            raise ValueError('row is outside basis span')
        previous, previous_coefficient = pivots[bit]
        value ^= previous
        coefficient ^= previous_coefficient
    return coefficient

class Edge:
    label: str
    source: int
    target: int

    B: tuple[int, ...]  # next-state rows over external-input coordinates
    c: int             # packed next-state affine offset
    O: tuple[int, ...]  # output rows over source-state coordinates
    D: tuple[int, ...]  # output rows over external-input coordinates
    e: int             # packed output affine offset

    input_dimension: int
    edges: tuple[Edge, ...]

def valid_integer(value, bits):
    return type(value) is int and 0 <= value < (1 << bits)


def check_machine_shape(machine):
    require(bool(machine.dimensions), 'missing control locations')
    require(all(type(n) is int and n >= 0 for n in machine.dimensions),
            'invalid state dimension')
    require(type(machine.input_dimension) is int and machine.input_dimension >= 0,
            'invalid input dimension')
    seen = set()
    for edge in machine.edges:
        require(type(edge.label) is str and bool(edge.label), 'invalid label')
        require(type(edge.source) is int and type(edge.target) is int and
                0 <= edge.source < len(machine.dimensions) and
                0 <= edge.target < len(machine.dimensions), 'invalid location')
        require((edge.source, edge.label) not in seen, 'ambiguous input label')
        seen.add((edge.source, edge.label))
        n, m = machine.dimensions[edge.source], machine.dimensions[edge.target]
        require(len(edge.A) == m and len(edge.B) == m, 'transition dimensions')
        require(all(valid_integer(r, n) for r in edge.A), 'invalid state matrix')
        require(all(valid_integer(r, machine.input_dimension) for r in edge.B),
                'invalid input matrix')
        require(valid_integer(edge.c, m), 'invalid affine state constant')
        require(len(edge.O) == len(edge.D), 'output dimensions')
        require(all(valid_integer(r, n) for r in edge.O), 'invalid observation')
        require(all(valid_integer(r, machine.input_dimension) for r in edge.D),
                'invalid direct input observation')
        require(valid_integer(edge.e, len(edge.O)), 'invalid output offset')


def close_observations(machine):
    """Least backward-closed row spaces, including every labeled transition."""
    check_machine_shape(machine)
    spaces = [canonical_basis(
        [r for edge in machine.edges if edge.source == loc for r in edge.O], n)
        for loc, n in enumerate(machine.dimensions)]
    initial_rank = sum(map(len, spaces))
    sweeps = 0
    while True:
        candidates = [list(basis) for basis in spaces]
        for edge in machine.edges:
            candidates[edge.source].extend(
                multiply(spaces[edge.target], edge.A))
        updated = [canonical_basis(rows, n)
                   for rows, n in zip(candidates, machine.dimensions)]
        if updated == spaces:
            break
        require(sum(map(len, updated)) > sum(map(len, spaces)),
                'nonterminal closure sweep must increase rank')
        spaces = updated
        sweeps += 1
    require(sweeps <= sum(machine.dimensions) - initial_rank, 'closure rank bound')
    return tuple(spaces), sweeps


def build_certificate(machine, bases):
    """Candidate construction; not the acceptance checker."""
    edges = []
    for edge in machine.edges:
        source_basis, target_basis = bases[edge.source], bases[edge.target]
        edges.append(replace(
            edge,
            A=tuple(coordinates(row, source_basis)
                    for row in multiply(target_basis, edge.A)),
            B=multiply(target_basis, edge.B),
            c=apply_bits(target_basis, edge.c),
            O=tuple(coordinates(row, source_basis) for row in edge.O)))
    return Certificate(bases, tuple(edges))


def validate_certificate(machine, certificate):
    """Independent identities on raw matrices, not rediscovery or sample tests.
    This establishes the matrix model's correspondence, not IR extraction,
    emitted Boundary records, ownership, effects, or economic minimality.
    """
    check_machine_shape(machine)
    require(len(certificate.bases) == len(machine.dimensions), 'missing basis')
    for basis, n in zip(certificate.bases, machine.dimensions):
        require(all(valid_integer(row, n) for row in basis), 'invalid basis row')
        # Independence is an output-format invariant, not the soundness theorem.
        # Insert pivots without calling the discovery canonicalizer.
        pivots = {}
        for row in basis:
            value = row
            while value:
                bit = value.bit_length() - 1
                if bit not in pivots:
                    pivots[bit] = value
                    break
                value ^= pivots[bit]
            require(value != 0, 'dependent basis row')
    reduced = Machine(tuple(map(len, certificate.bases)),
                      machine.input_dimension, certificate.edges)
    check_machine_shape(reduced)
    require(len(machine.edges) == len(certificate.edges), 'missing action')
    for old, new in zip(machine.edges, certificate.edges):
        require((old.label, old.source, old.target) ==
                (new.label, new.source, new.target), 'changed action/control')
        hs, ht = certificate.bases[old.source], certificate.bases[old.target]
        require(multiply(ht, old.A) == multiply(new.A, hs), 'transition equation')
        require(new.B == multiply(ht, old.B), 'input equation')
        require(new.c == apply_bits(ht, old.c), 'affine state equation')
        require(old.O == multiply(new.O, hs), 'observation equation')
        require(new.D == old.D and new.e == old.e, 'direct output equation')
    return reduced


def slow_evaluate(rows, value, width):
    """Oracle evaluation deliberately uses explicit arithmetic, not matrix ops."""
    output = 0
    for j, row in enumerate(rows):
        bit = sum(((row // (2 ** i)) % 2) * ((value // (2 ** i)) % 2)
                  for i in range(width)) % 2
        output += bit * (2 ** j)
    return output


def oracle_tables(machine):
    states = tuple((loc, x) for loc, n in enumerate(machine.dimensions)
                   for x in range(1 << n))
    outputs, successors, labels = {}, {}, {}
    for state in states:
        loc, x = state
        observations, following, actions = [], [], []
        for edge in machine.edges:
            if edge.source != loc:
                continue
            for u in range(1 << machine.input_dimension):
                observations.append(
                    slow_evaluate(edge.O, x, machine.dimensions[loc]) ^
                    slow_evaluate(edge.D, u, machine.input_dimension) ^ edge.e)
                following.append((edge.target,
                    slow_evaluate(edge.A, x, machine.dimensions[loc]) ^
                    slow_evaluate(edge.B, u, machine.input_dimension) ^ edge.c))
                actions.append((edge.label, u))
        outputs[state], successors[state], labels[state] = (
            tuple(observations), tuple(following), tuple(actions))
    return states, outputs, successors, labels


def exact_behavior_partition(machine):
    """Independent finite-state oracle; knows no GF(2) invariant subspaces."""
    states, outputs, following, _ = oracle_tables(machine)
    classes = {state: state[0] for state in states}
    while True:
        index, next_classes = {}, {}
        for state in states:
            key = (state[0], outputs[state],
                   tuple(classes[next_state] for next_state in following[state]))
            next_classes[state] = index.setdefault(key, len(index))
        if all((classes[a] == classes[b]) == (next_classes[a] == next_classes[b])
               for a in states for b in states):
            return next_classes
        classes = next_classes


def shortest_distinguishing_suffix(machine, left, right):
    _, outputs, following, labels = oracle_tables(machine)
    require(left[0] == right[0], 'different control locations')
    queue = deque([(left, right, ())])
    seen = {(left, right)}
    while queue:
        a, b, prefix = queue.popleft()
        for i, action in enumerate(labels[a]):
            path = prefix + (action,)
            if outputs[a][i] != outputs[b][i]:
                return path
            pair = (following[a][i], following[b][i])
            if pair not in seen:
                seen.add(pair)
                queue.append((*pair, path))
    return None

        bases, _ = close_observations(machine)
    certificate = build_certificate(machine, bases)
    reduced = validate_certificate(machine, certificate)
    partition = exact_behavior_partition(machine)
    # Both maps must induce precisely the same equivalence, location by location.
    forward, reverse = {}, {}
    for state, behavior_class in partition.items():

        require(forward.setdefault(code, behavior_class) == behavior_class,
                'summary lost future behavior')
        require(reverse.setdefault(behavior_class, code) == code,
```
